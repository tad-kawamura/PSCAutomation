# WF1973 の実機確認(移植後、2026-11-04)

移植後の `Wrappers/Instruments` の WF1973 用 3 クラスを、実機の WF1973(NF Corporation,WF1973,9218487,Ver2.50、USB)で動かした記録。
WF1973 の出力(指令電圧)を NR-500 の CH4 に 20ms で 40 秒記録し、保存した xdt から判定した。弁(AS110)と 7351E はつないだまま(1V = 6mA)。

## 確認したこと

| クラス | 確認の方法 | 結果 |
|---|---|---|
| `Wf1973DcSource`(DC) | AS110NoiseTest の実機確認(`MeasurementCheck --real`、7〜30mA の通し・中断) | OK。電圧の変更・出力 ON / OFF、終了時の 0V・出力 OFF(前面パネルで目視)。詳細は `Apps/AS110NoiseTest/README.md` |
| `Wf1973BurstSession`(バースト。`FunctionGeneratorConnection.Connect` で接続) | `Instruments.HardwareCheck burst` | OK(下の表) |
| `Wf1973ContinuousSession`(連続) | `Instruments.HardwareCheck continuous` | OK(下の表) |

### バースト(旧 AS110AllCheck の設定)

動き検査(0.2Hz・10.2Vpp・オフセット 0・0.5 周期・開始位相 0°)を 2 回、データ取り(0.04Hz)を 1 回、リーク用の DC 5V(`SetDcOutput(5)`)を約 4 秒、`StopOutput` の順。

| 項目 | 結果 |
|---|---|
| 動き検査 1 回目(出力 ON + `*TRG`) | 0V → 5.105V → 0V の三角。0.25V を超えた時間 2.38 秒(期待 2.38) |
| 動き検査 2 回目(`*TRG` だけ。準備は再送しない) | 同じ形。最大 5.097V。1 回目と同じ遅れで出る |
| データ取り(準備し直して `*TRG`) | 0V → 5.107V → 0V、12.5 秒の山(0.25V 超え 11.92 秒、期待 11.89) |
| リーク DC 5V | 5.001V、平らな部分の振れ 0.005V。**`SetDcOutput` を呼んでから約 0.16 秒後に出る**(バーストの `*TRG` より遅い。波形を DC に切り替えるため) |
| 出していないとき | 振れ最大 0.023V(2 回目の前、データ取りの準備中、`StopOutput` の後) |

### 連続(旧 AS100201SwitchController の位相)

旧アプリの本来の設定(10.2Vpp・オフセット 0・0.02Hz)は ±5.1V で負の電圧が出るので、弁をつないだまま試せる **5.1Vpp・オフセット 2.55V(0〜5.1V)・0.1Hz** に変えた。位相は旧アプリと同じ 15° で始め、約 12.5 秒後に 165° で出し直した。

| 項目 | 結果 |
|---|---|
| 振幅・周期 | 最小 0.010V / 最大 5.106V、中心を横切る間隔 4.98〜5.02 秒(期待 5.00) |
| 開始の位相 | 16°(設定 15°)。中心を上りで横切る点を 0° とする |
| 出し直し(15° → 165°、出力は ON のまま) | 165° からやり直した(出し直さなければ 103° だったところが 162°) |
| 出力 OFF(連続のクラスは Dispose で切らないので、接続し直して `:OUTPut:STATe OFF`) | OFF 後の振れ 0.006V |

## 分かったこと(アプリ側で気にすること)

- **連続のクラスは波形の形(三角・正弦など)を送らない**。本体に残っている形のまま出る(旧 SwitchController と同じ)。同じ WF1973 を AS110NoiseTest(DC)や `SetDcOutput` の後に使うと DC のままになる。確認ツールでは先にバーストのクラスで三角波にしてから使った。SwitchController を移植するときに、形を送る部品を足すかどうかを決める
- **連続の出し直しは段差が 2 回出る**。`:PHASe 165` を送った時点でまず設定の差(150°)だけずれ(記録では 4.781V → 0.513V)、約 80ms 後に `:PHASe:INITiate` で 165° からやり直す(0.450V → 2.983V)。旧 SwitchController と同じ順番で送っているので、旧アプリでも同じはず。この 80ms の段差が困るかどうかは AS100-201 側で判断する
- 位相 0° の三角は中心(オフセット)から上り始める。AS110AllCheck の 0.5 周期・開始位相 0° は 0V → 山 → 0V の山 1 つになる(上の結果のとおり)
- 位相を変えずに出し直した場合(0° → 0°)も、`:PHASe:INITiate` で 0° からやり直した(段差は 1 回)

## 確認していないこと

- SDG1032X(この PC につないでいない)
- 旧 SwitchController の本来の振幅(±5.1V、負の電圧)と 0.02Hz。負の電圧を AS110 の弁に入れないため
- 旧アプリの画面からの操作(AllCheck の測定フロー、SwitchController の押下連打の途中での中断 `superseded`)。確認したのは wrapper のクラスを直接呼んだ場合だけ

## 確認ツール

`Wrappers/Tests/Instruments.HardwareCheck`。NR-500 と WAVE LOGGER(旧)を使い、AS110NoiseTest の雛形 xdt(CH4 = 指令電圧)で記録する。

```
dotnet run --project Wrappers/Tests/Instruments.HardwareCheck -- burst --out C:\AS110Noise\WF1973確認
dotnet run --project Wrappers/Tests/Instruments.HardwareCheck -- continuous --out C:\AS110Noise\WF1973確認
dotnet run --project Wrappers/Tests/Instruments.HardwareCheck -- analyze continuous <xdt> --dump 14.5 14.9   # 保存済みの xdt を判定・値を並べる(機器なし)
```

出す電圧は 0〜+5.1V(30.6mA まで)に収めてある。ほかの LOGGER 画面は閉じておく。
