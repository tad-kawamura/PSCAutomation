# XDTバイナリ項目一覧と調査結果

調査日: 2026-10-26。対象は同梱の `b / c / loggerX / PC / CR.xdt` の5ファイル。
メーカー公表のバイナリ仕様ではなく、実ファイルの解析とメーカーソフトの出力による検証結果です。
範囲外の形式・機器・設定に適用できるとは断定しません。YDTは未解析・未対応です。

## 表記と検証方法

- オフセットはファイル先頭を0とする**バイト位置、10進数**。数値はlittle-endian。
- `uint16/uint32/uint64` は符号なし整数、`int32` は符号付き整数、`float32` はIEEE 754単精度。
- 同梱XDTを、このPCにインストール済みのWAVE LOGGER Xの公式COM APIで開き、`SaveCsvFile` で別の作業領域へ書き出して照合した。元XDTの書換えは行っていない。
- CSVヘッダの周期・収集開始日時・点数・波形名・単位・スケーリング・スムージングと、先頭・最終データの日時を照合した。
- CSVは表示桁数に丸められる。数値の全点検証には従来からの `.bin` 参照値を使用し、絶対誤差0.0002以内を確認する。
- CSVの必要項目と元XDTのSHA-256を `Verification/Fixtures/timing-reference.json` に保存。時刻の期待値をXDTから逆算して作成していない。
- メーカー提供のローカル資料: `C:/Program Files (x86)/KEYENCE/WAVE LOGGER X/WLXAuto_M_E.pdf`。本文p.40にCSV保存、p.47–49にスケーリング・スムージング前の値を得るAPI、p.6に日時取得の制限がある。COM自体は製品ライブラリに不要。

日時はWindows FILETIMEと同じ数値表現だが、UTCであるとは確認できていない。
**PCのタイムゾーン変換を適用せず、CSVと同じカレンダー値を `DateTimeKind.Unspecified` で返す。**
0や範囲外の日時は `null` とし、元のuint64値も保持する。

未確認の単位コードや周期0では、`SampleInterval` とそれを必要とする計算値を `null` にする。
波形の読み取りは継続できる。未確認コードを秒・nsなどに推測変換しない。

## 波形ヘッダと測定値

Hは下記条件で一意に探索する可変位置。N=CH当たりの保存点数、C=保存CH数。
固定の「ファイル先頭から何バイト目」で波形開始を決めない。

| 位置 | バイト数 / 型 | 内容 |
| --- | --- | --- |
| H−4 | 4 / uint32 | CH番号リストのバイト数 = 4×C |
| H | 4 / uint32 | N（共通ヘッダのNと一致） |
| H+4 | 4 / uint32 | C（1～256） |
| H+8 | 4 / uint32 | 全例0。意味未確認、対応形式の探索条件 |
| H+12 | 4×C / int32[] | 0始まりCH番号。重複不可。配列順が波形の列順 |
| D=H+12+4×C | 4×N×C / float32[] | 保存測定値。スケーリング・スムージング前 |
| E=D+4×N×C | 36 / bytes | 末尾領域。先頭uint32は2、残りの意味は未確認 |

`E+36 == ファイルサイズ` を必須とし、候補が0個または複数なら例外にする。
測定値は**サンプル優先**で、`sample0の全CH → sample1の全CH → …`。

```
測定値の位置 = D + 4 * (sampleIndex * C + columnIndex)
```

sampleIndexとcolumnIndexは0始まり。columnIndexはCH番号リスト内の位置で、CH番号そのものではない。
APIのCH番号は1始まり。たとえばPC/CRにはCH3がなく、CH5は4番目の波形列に入る。
使用CH数はここに保存されたCH数を意味し、機器の最大CH数や全設定CH数とは区別する。

## CH設定ブロック

`id=CH番号−1`。**ブロック先頭Bは旧LOGGERで796+68×id、LOGGER Xで1100+92×id**。
旧コードの797は文字列の先頭ではなく、読み取りに使っていた便宜上の基準点。今回、名前を含むブロック先頭796へ揃えた。
以下はBからの相対位置。

| 項目 | 旧相対位置 | X相対位置 | バイト数（旧 / X）・型 | 解釈 |
| --- | ---: | ---: | --- | --- |
| 波形名 | 0 | 0 | 16 / 32、CP932 / UTF-16LE | NUL終端。日本語・半角カナをCSVと照合 |
| スケーリング有効 | 20 | 36 | 4 / uint32 | 0=無効、1=有効 |
| 入力値1 x1 | 24 | 40 | 4 / float32 | スケーリング第1点 |
| 表示値1 y1 | 28 | 44 | 4 / float32 | 同上 |
| 入力値2 x2 | 32 | 48 | 4 / float32 | スケーリング第2点 |
| 表示値2 y2 | 36 | 52 | 4 / float32 | 同上 |
| 表示単位 | 40 | 56 | 8 / 16、CP932 / UTF-16LE | V、kPa、μm、L/min等。無効時も保存文字列をそのまま返す |
| 移動平均有効 | 48 | 72 | 4 / uint32 | 0=無効、1=有効 |
| 移動平均窓の点数 | 52 | 76 | 4 / uint32 | 有効時は1以上。無効時にも設定値が残る |

スケーリング無効のLOGGER X CH2は保存単位文字列が空で、CSVでは入力レンジ由来の「V」が表示される。
wrapperの `Unit` は保存文字列を返し、入力レンジから既定単位を推測して補完しない。

この表に含まれないブロック内の領域（入力レンジ・計測機能等）は、存在しても意味を確定していない。
その設定値を生データに再適用しない。特に、cのCSVにある機器の「平均回数128回」と後処理の移動平均は別のもの。

```
gain   = (y2-y1)/(x2-x1)
offset = y1-gain*x1
scaled = (float)(gain*raw + offset)
```

floatパラメータをdoubleにしてから倍率・オフセットを計算し、各点をfloatへ丸める従来挙動を保持。
スケーリング無効時はgain=1、offset=0。設定点そのものもAPIに残す。
移動平均は中央窓 `i−window/2 ... i−window/2+window−1`、端は存在する点だけを平均しfloatへ丸める。
偶数窓では左右対称にならない。間引きはライブラリの外で、後処理後に行う。

**測定時間という単一のプロパティにはしない。**

- `AcquisitionStart`: 収集開始。待機・トリガ待ちを含み得る。
- `FirstSample`: 保存された最初のデータ日時。必ずしも収集開始と一致しない。
- `SampleSpan`: 最初のデータから最終データまで、(N−1)×周期。
- `RecordLength`: N×周期。各サンプルに1周期を割り当てた収録長の定義。機器の実停止日時ではない。
- `LastSample`: FirstSample + SampleSpan。ファイルに終了日時が保存されているという意味ではない。

loggerXではCSVのプリトリガ設定がONで、開始から先頭データまで4.1秒ある。
この差をトリガ発生時刻・実測停止時刻と同一視しない。

## 未確定・今後の対象

- 周期単位コード2/3以外、日時のタイムゾーン、トリガ発生日時、実際の停止日時。
- 他機器・複数ユニット・複数グループ・演算CH・圧縮保存・連続収集等で同じ構造になるか。
- 無効値・オーバーレンジの機器固有センチネル値。現在は非有限値を拒否するが、有限の特別値の意味は未解釈。
- ファイルヘッダ、CH設定、末尾の未掲載領域。未確認バイトを意味のある値として公開しない。
- YDT。NR-X100系の別ドキュメントとして公式APIにも区分されているため、XDTのオフセットを流用しない。実サンプルと公式CSVを用意して個別に調査する。

## 再利用の入口

`XdtConversion.Core` は `net9.0` の独立ライブラリ。Windows Forms、Excel、メーカーソフト、外部NuGetパッケージに依存しない。
使い方と検証コマンドは [wrapperの説明](XDT-WRAPPER.md) を参照。
各実ファイルに適用したバイト位置は `file.Info.BinaryFields` で取得できる。
