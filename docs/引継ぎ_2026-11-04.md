# 引継ぎ:wrapper一元管理とチーム向けAI開発フロー

(2026-11-04 にプロジェクト開始時に受け取った引継ぎ文書。原文のまま保存)

## 目的
AI未経験のメンバーでも、ハード連携アプリ(マイコン・発振器・計測器)の
仕様決め〜開発ができる仕組みを作る。

## 背景
- 現状:AS110AllCheck をクローンしてもらい、AIがwrapperを読むことで
  使用機器の前提すり合わせを省いている
- 課題:wrapperが複数リポジトリに散らばっている
  (AS110AllCheck / AS110BoltCheck / AS100201SwitchController /
   XdtConversion / AS110NoiseTest、すべてPrivate)
- 初心者は「何ができるか」を知らないため、オープンな質問には答えられない

## 決定事項
1. モノレポ化:新リポジトリに全アプリと共通wrapperを集約する
2. 各アプリは Wrappers をプロジェクト参照する(exeはアプリごとに別)
3. 普段はソリューションフィルター(.slnf)でアプリ単位に作業し、
   wrapper変更時のみ全体 .sln をビルドして確認する
4. ルール本体は AGENTS.md に書き、CLAUDE.md は `@AGENTS.md` の1行のみとする
5. superpowers は導入しない。仕様決めのルールを AGENTS.md に自前で書く

## 目標構成
```
AS110Tools/
├── AGENTS.md / CLAUDE.md
├── docs/capabilities.md   ← wrapperの機能一覧(できること・制約)
├── Wrappers/              ← 共通wrapper(C#クラスライブラリ)
├── Apps/<各アプリ>/
├── specs/                 ← 仕様インタビューで作った SPEC.md
├── AS110Tools.sln
└── *.slnf                 ← アプリ別フィルター
```
- .gitignore で bin/ obj/ と計測データ・ログを除外する

## AGENTS.md に書くルール
### 仕様決め
- 新しい依頼には、すぐにコードを書かない
- wrapper と capabilities.md を読み、実現できる範囲から
  **選択肢と、それぞれを選んだ結果をセットで**提示して質問する
- 質問の順番:目的 → 使う機器 → 入出力 → 異常時 → 細部
- 決まった内容を specs/ に SPEC.md としてまとめ、承認されるまで実装しない
- 小さな修正では、この手順を省略してよい

### wrapperとアプリ側の切り分け
- wrapper:機器との通信・コマンド送受信・接続/切断など、どのアプリでも同じ機器操作
- アプリ側:判定ロジック、画面、試験手順、アプリ固有の設定値
- wrapperを変更するとき
  - 既存の関数の動作は変えない(必要なら新しい関数を追加する)
  - 変更前に人間へ「全アプリに影響する」と確認を取る
  - 変更後は全体 .sln をビルドして、他アプリが壊れていないか確認する

## 次にやること
1. 5つのリポジトリのwrapperを比較し、差分と統合方針を人間に報告する
2. 新リポジトリを作成し、コードを移す(旧リポジトリはアーカイブ)
3. .sln / .slnf / .gitignore を整備する
4. AGENTS.md・CLAUDE.md・capabilities.md を作成する
5. 全アプリのビルドが通ることを確認する
