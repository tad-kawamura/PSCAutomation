### アプリを移すときに直すこと

- 起動時に `ArduinoDiagnosticLog.Configure(...)` を呼ぶ。AllCheck の固有種別は `"NF_STALE", "FRAME_GAP", "NF_RECOVERY_START"`(元 AllCheck 版の直書きの一覧と共通一覧の差)。SwitchController は `As100201Application.ConfigureDiagnostics()` がそのまま使える。
- AllCheck: 元はログの代わりの保存先が `%LOCALAPPDATA%\AS110BoltCheck\Logs` 直書きだった。`Configure("AS110AllCheck", ...)` にすると保存先が変わる(元のフォルダー名を保ちたいなら `"AS110BoltCheck"` を渡す)。
- AllCheck: 元の AllCheck 版は `READER_ERROR` を異常種別に入れていなかった(SwitchController 版は入れていた)。統合版では `READER_ERROR` でも異常ログを保存し始める。
- `PcDelayObservation.Start()` は `PcDelayObservation.Start(ArduinoDiagnosticLog.Write)` にする(手順 2 のとおり)。
- `using PSCAutomation.Wrappers.Arduino;` と `using PSCAutomation.Wrappers.Common;` を足す。

### 旧 Verification の Excel 転送検査が A6 で止まっていた件(直した)

- 原因: 旧検証は「雛形の Sheet1 の A6 以降に前回の転送値が入っている」前提で、雛形の値と変換後の値を比べていた。同梱の `雛形.xlsx` は Sheet1(`xl/worksheets/sheet2.xml`)の A6 以降が空なので、`oldCells["A6"]` が `KeyNotFoundException` になっていた(旧 README の「66 行目で A6」)。値の入ったブックを前提に書いた検査を、値を消した雛形のまま登録したためと推測する(旧リポジトリの履歴では、雛形は最初のコミットから今の内容)。変換そのものの不具合ではない。
- 直し方: 比較の相手を、独立の参照値(`Fixtures/PC.bin`・`CR.bin`、メーカーソフトで出した全点の値)を 10 点おきに取ったものにした(許容差 0.0002、xdt 照合と同じ)。転送点数が 5,000 点であること、5,001 点目が空であることも確かめる。シート名からワークシートのパーツを引くようにした(旧検証は `sheet2.xml` 直書き)。
- 追加: 旧アプリの出力と比べる `--compare-old <xlsx>`。旧リポジトリの `…_変換_20261008_144212413.xlsx`(2026-10-08 に旧アプリが同じ PC / CR の xdt・既定設定で出力したもの)と、A・B・H・I 列の 6〜5005 行(20,000 セル)が文字列として一致した。
- 追加した検査: 間引き数 0、CR の xdt 未指定(`ConversionService` の入口)。
