# 実機確認チェックリスト(出社日用)

2026-11-21 作成。家では機器なしの検査・模擬(`--sim`・互換テスト・`FakeInstrument`)で確かめ、**実機が要るものだけを出社日にまとめて確かめる**ための一覧。アプリをまたいで、優先度の順に並べた。

- 書き方: 「すること → こうなれば良い」。★ は特に大事なもの
- 確かめたらチェックを付け、違ったこと・測った秒数や値はその行の下に書く。家に戻って AI に伝えれば、各アプリの README・STATUS.md・`docs/残課題.md` に書き写す
- 細かい手順と全項目は、各節の「元」の文書にある。ここはその日に何をどの順でやるかを決めるための入口
- 機器に電圧・電流を出す確認は、必ず人が機器のそばにいる状態で行う(弁・試験対象をつないだまま遠隔で動かさない)

## 0. 出社前(家で)

- [ ] 家で直したものを push してある(`AGENTS.md`「家の PC からの push」)
- [ ] その日に確かめるアプリを、下の節から選んでおく(全部は 1 日で終わらない)
- [ ] 家で確かめられない点・気になる点があれば、該当する行の下に書いておく

- [ ] 機器の USB をつなぎ、電源を入れる。使う雛形が `雛形` フォルダーにそろっているか見る

まず次の ★ を確かめる(STATUS.md の「次にやること」の 0.〜1.)。

- [ ] ★ 現場で使っている ver3.02 で、AS110-015 の参照波形を選ぶと型式が替わる。そのあとのデータ取り(転送・判定・保存・漏れ試験)が通る
- [ ] ★ ① の微調整: 7351E が 0 mA ±0.1 mA に入る(下限 -0.5 V。そのときの電圧が負になるかも書く)
- [ ] ★ 最初の画面: 校正のあと立ち上げ直すと、すぐ「今日の校正：済み」で「測定」が押せる(2026-11-19 の不具合の直し)
- [ ] 2026-11-20 に作り直した校正画面(手順 1〜3 の枠・次に押す所の色・指示の文)で、迷わず押せる
- [ ] ★ 試し版を初めて起動する前に、ver3.01 の転送設定の表と漏れ試験の欄を写真に撮る(初めての起動でしか見られない引き継ぎの確認のため)

時間があれば、`real-device-checks.md` の 1.〜12. を上から進める。特に ★ の付いた、漏れ試験で不合格のあと「合格」を押せないこと(5.)は、逃げ道が無くなったので大事。

## 3. AS110NoiseTest(優先度: 高。ただし 2026-11-05 から止まっている)

- [ ] LOGGER 画面の p-p と、アプリの判定の目視照合(9 mA・28 mA 以外の残り 22 本)

## 4. AS100201SwitchController(優先度: 中。実際の作業で見るもの)

元: `Apps/AS100201SwitchController/STATUS.md`、`Apps/AS100201SwitchController/README.md`「Tab5 を Wi-Fi・電池で使う」「確認した範囲と未確認(学習モード)」

つなぐもの: Tab5(電池・Wi-Fi)・PC の子機(BUFFALO WI-U2-150M)・Arduino・WF1973・NR-500

- [ ] ★ 実際の調整作業で、1 個体ぶんを学習モードで記録する(台帳・xdt・取り込みの CSV)。作業のあいだ Wi-Fi が勝手に切れないか
- [ ] 画面を暗くする・最初のタッチを捨てる動き。電池のもち(作業の始めと終わりの残量を書く)、充電中の表示、電池なしのときのアプリの画面
- [ ] Wi-Fi でつないでいる最中に「確認」を押すと USB に戻る
- [ ] Wi-Fi での定期応答の止まり(操作禁止)がどのくらい出るか(回数と長さを書く)
- [ ] PC の子機を抜いてから Tab5 に「PC と切れました（Wi-Fi）」が出るまでの秒数(見込み約 6 秒)。子機を挿し直す・USB を挿したあとに、つながり直す
- [ ] 2 回押し(試用中)と位相の入力: 1 回押し・2 回押しの判定、2 回押しの位相(75° / 250°)と 1 回押しの位相(0° / 140°)での出し直しの波形(目視・ロガー)

README の「未確認」には、その後に済んだものも混ざっている(例: 版 4 で USB を抜いたときの問題は 2026-11-17 に対処済み)。上に挙げた以外を確かめるときは、先に AI と今も残っているものを整理する。
