# AS100201SwitchController 追加仕様: 測定中の取り込みと加工(学習モード)

学習モードで、測定中の LOGGER から値をリアルタイムに取り込み、大きさ・傾きなどに加工して残す。ゆくゆく、加工した値から AI が「今どの操作をするのが完成に最も近づくか」を測定中に表示するための下地。

- 状態: **承認済み・実装済み・アプリでの実機は一部確認**(2026-11-11 の相談で決め、同日に人が承認(共通部分への関数追加を含む)。同日実装し、アプリの画面から NR-500・旧 WAVE LOGGER で取り込み → 操作ボタンで停止 → CSV が xdt と全行一致まで確認。三角波の出ている波形・USB を抜いたときなどは未確認。詳細は `Apps/AS100201SwitchController/README.md`「測定中の取り込み」)
- 本体の仕様は [SPEC.md](SPEC.md)、学習モードの仕様は [SPEC_調整操作の記録.md](SPEC_調整操作の記録.md)。この文書は追加分だけを書く
- 「AI の仮決め」と書いた項目は、人が決めていない細部を AI が決めたもの。異論があれば変える

## 背景と目的

- 学習モードで「測定 → 操作 → 測定」の記録(xdt と台帳)を貯めている。データが貯まったら、熟練者の調整を AI に学ばせ、**測定中に**次の操作を助言させたい(人の目的)
- LOGGER の画面にはもともと波形がリアルタイムで出ている。アプリで取り込む意味は、AI に渡す形(大きさ・傾きなど)に加工すること。**取り込んだ値そのものは画面に出さない**(人の回答)
- 測定中の取り出しは、NR-500・旧 WAVE LOGGER で実機確認済み(2026-11-11、`Wrappers/Tests/WaveLogger.LiveReadCheck`。遅れ平均 0.07 秒・最大 0.17 秒、1 回の読み取り平均 12ms、保存した xdt と全点一致)

## 決めたこと(2026-11-11)

| 項目 | 決めた内容 | ほかの選択肢(選ばなかった理由) |
|---|---|---|
| 今回作る範囲 | **取り込みと加工まで**。AI と助言の表示は作らない(AI はデータが貯まってから) | 熟練者のコツを手でルールにして仮の助言を出す(聞き出す手間、AI ができたら置き換え)/ 保存済みの xdt から加工するだけ(測定中の取り込みを後回し) |
| 助言を出す時機(加工の時機) | **測定中ずっと更新する**(0.2 秒ごと)。AI も「測定開始からその時点までの波形」で学ばせる | 三角波 1 周期・片道ごと(最初の助言まで最短 25 秒)/ 測定を止めたとき(測定中に助言が出ない) |
| 加工する値の決め方 | **熟練者に聞かず、データから判断できるようにする**。候補を広く計算して残し、AI を作るときにどれが効くかをデータで選ぶ。熟練者が気づいていない、もっと早く調整できる手がかりを先入観で落とさないため(人の回答) | 熟練者に何を見ているか聞いて、その値だけ計算する(本人が意識していない手がかりを落とす) |
| 加工した値を残すか | **測定ごとに別ファイル(CSV)で残す**。xdt と同じ日付フォルダーに同じ名前で置く。台帳の列は変えない | 残さない(測定中の計算が正しいか調べにくい) |
| 動かすモード | **学習モードだけ**。通常モードは何も変えない | 両方(通常モードの実機確認のやり直し) |
| 取り込みに失敗したとき | **測定も止めて知らせる**(下の「異常時」) | 加工だけ止めて測定は続ける(作業は止まらないが、異常に気づきにくい) |
| 助言の表示先 | **保留**(PC の画面かタッチパネルか、AI ができてから決める。人の回答) | — |

## 使う機器

変わらない。LOGGER と本体は今までどおり USB。

- 実機確認済みは **NR-500 + 旧 WAVE LOGGER** だけ。WAVE LOGGER X・NR-X で使う場合は、確認ツールで先に確かめる(同名の関数があることは型情報で確認済み)

## 動き

1. 学習モードで LOGGER が測定中になったら(F8・画面の「測定開始（確認用）」)、0.2 秒ごとに LOGGER から、前回の続きの点を取り出す(`GetDataCount` → `GetArrayData`)
2. 取り出した値を雛形の換算係数で換算する(電圧 → mA・kPa など。保存した xdt の値と一致することを確認済み)
3. 測定開始からその時点までの点で、下の「加工する値」を計算し、1 行として覚えておく
4. 測定が止まったら(sw4・操作ボタン・LOGGER の自動停止)、今までどおり台帳の行と xdt を残したあと、覚えておいた行を CSV に書く。書けないときは xdt と同じ扱い(最前面の「再試行」「キャンセル」、保存できるまで次の測定を受け付けない)

- 取り込みは画面のスレッドで行う(LOGGER の部品の決まり)。1 回 12ms 前後、まれに 90ms ほどかかる。その間に押されたスイッチ(PC_go / CR_go の位相の出し直し)は最大 0.1 秒ほど遅れることがある(三角波 1 周期 50 秒に対して約 0.7°)
- 画面には取り込んだ値を出さない。ログには測定ごとに「取り込み: N 回、点数 M」だけ出す(AI の仮決め)

## 加工する値(AI の仮決め。xdt が残るので、後から変えて計算し直せる)

熟練者の判断を前提にせず、どの波形にも当てはまる一般的な値を広く取る。対象は雛形の全チャンネル(CH1 指令、CH2 電流モニタ、CH3 圧力、CH5 流量、CH6 Ps2)。1 行 = 0.2 秒ごとの 1 回。

| 区分 | 値 |
|---|---|
| 行の情報 | 取り込み回、時刻、F8 からの秒、側(PC / CR / 2 回押し)、位相(ここまでは xdt に無いので、xdt との突き合わせでは比べない)。点数、データの秒(点数 × 周期)、指令の向き(上り / 下り / 平ら。CH1 の 1 秒前との差が ±0.05 / 秒を超えるか。先頭 1 秒は空欄) |
| 各チャンネルの今 | 直近 0.2 秒の平均 |
| 各チャンネルの開始からの集計 | 最大、最小、平均、標準偏差 |
| 各チャンネルの時間に対する傾き | 直近 1 秒・直近 5 秒の回帰直線の傾き(単位 / 秒) |
| 指令に対する傾き(CH1 以外) | 直近 5 秒の「値 対 CH1 指令」の回帰直線の傾き |
| 上りと下りの差(CH1 以外) | 指令の範囲(測定開始からの最小〜最大)を 10 区間に分け、区間ごとに上りの点の平均・下りの点の平均・その差(まだ通っていない区間・平らな点は使わない・空欄) |

- 雛形の 5 チャンネル(CH1・2・3・5・6)では 1 行 167 欄(行の情報 5 + 点数など 3 + チャンネルごと 7 × 5 + 指令に対する傾き 4 + 区間 30 × 4)
- 行は点が増えた回だけ足す(増えなかった回は同じ値になるため)。最後の行(停止後に残りを取り出した行)は xdt の全点で計算した値
- 換算は保存した xdt の換算(`XdtChannel.ReadScaledValues`)と同じ。移動平均(LOGGER の表示の設定)はかけない

- 同じ計算を、保存した xdt の「記録開始からその秒まで」に当てはめると同じ値になるように作る(AI に学ばせるときは xdt から計算し直せる。この CSV は「測定中に計算した値が xdt から計算した値と同じ」ことの確認にも使う)
- 計算の部品は機器から切り離し(点の並びを受け取って値を返すだけ)、機器なしで xdt から計算するテストを作る
- 実機で残った CSV と xdt の突き合わせ: `AS100201.RegressionTests.exe --compare-features <xdt>`(同じ名前の .csv と比べる。一致で終了コード 0)

## 出力

- CSV: `学習データ\yyyyMMdd\<xdt と同じ名前>.csv`(例: `20261111_101530_PC.csv`)。UTF-8(BOM 付き)、先頭にヘッダー行、1 行 = 0.2 秒ごとの 1 回。1 分でおよそ 290 行・約 210KB(2026-11-11 の実機で 226 秒・1085 行・約 780KB。最初は「最長約 51 秒で約 250 行」と書いたが、雛形は約 51 秒では自動で止まらず、止めるまで続いた)
- 台帳(`調整記録.csv`)の列は変えない。CSV は xdt と同じ名前なので、台帳の「ファイル」列からたどれる
- 停止のきっかけに「取り込み異常」を足す(台帳の「停止のきっかけ」列の値が 1 つ増える。列は変えない)

## 異常時

取り込みに失敗したと判断するのは次のとき(AI の仮決め):

- LOGGER の関数が例外を返した
- 測定中なのに、点数が 2 秒増えない(実機の遅れは最大 0.17 秒)
- 点数が減った・取り出した点数が足りない
- 雛形から換算係数を読めない(測定開始前に分かるので、F8 を受け付けずログに出す)

失敗したら:

1. LOGGER を止める(sw4 と同じ)
2. 台帳に測定の行(停止のきっかけ = 取り込み異常)を書き、xdt と、そこまでの CSV を保存する(学習データは欠けない)
3. 最前面の窓で「測定中の取り込みに失敗したので測定を止めました」と理由を知らせる。異常ログにも残す
4. 次の F8 でまた取り込みを試す(取り込みのために操作を禁止したりはしない)

## 共通部分の変更(全アプリに影響)

LOGGER の部品(`Wrappers/WaveLogger.Automation` の `WaveLoggerSession`)に、値を取り出す関数を**足す**(`GetDataCount` / `GetArrayData` / `GetCurrentData` を包むもの)。

- 既存の関数の動作は変えないので、ほかのアプリ(AS110AllCheck・AS110NoiseTest など)は書き換え不要
- 変更後に全体 `.sln` のビルドと `Wrappers/` のテストを行い、`docs/capabilities.md` を更新する
- 確認ツール `WaveLogger.LiveReadCheck` は、リフレクションで借りている呼び出しを新しい関数に乗り換える

## 変えないこと

- 通常モードの動き
- 学習モードの今の動き(スイッチ・タッチパネル・台帳・xdt の保存)。取り込みは追加するだけ

## 確認の予定(実装後)

- 模擬: 加工の計算(手で作った点の並び・学習データの xdt で、値と「途中まで」の切り出しが合うこと)、失敗の判断(例外・点数が増えない・減る)、CSV の名前と置き場
- 実機(NR-500・旧 WAVE LOGGER): 学習モードで F8 → sw4 / 操作ボタン / 自動停止、CSV ができて xdt から計算した値と一致すること、取り込み中の PC_go / CR_go の遅れ(ログの時刻)、LOGGER の USB を抜いて取り込み異常で止まること
  - 2026-11-11 に済んだもの: 画面の「測定開始（確認用）」→ 操作ボタン(開発用の代わりの「着磁」)で停止、CSV が xdt と全 1085 行一致、取り込みの間隔(最大 0.418 秒)と遅れ(平均 0.063 秒・最大 0.195 秒)
  - 残り: 三角波の出ている波形(PC_go / CR_go を押す)、sw4 での停止、PC_go / CR_go の遅れ、USB を抜いたときの取り込み異常。どれも人がスイッチを押す・ケーブルを抜く必要がある
