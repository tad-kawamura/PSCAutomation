# AS100201SwitchController 仕様(2026-11-04 移植時に整理)

移植前のリポジトリ AS100201SwitchController(`5eb5b63`、2026-10-28)の README・コードの動きを、雛形の形にまとめ直したもの。移植前に実機で使われていた動きはそのまま残した。**移植時に人と決めて変えたこと**は「移植で変えたこと」に分けて書く。

- 状態: **仕様確定**(2026-11-04、人の確認)。移植・実機確認済み(確認した範囲は `Apps/AS100201SwitchController/README.md`)
- 追加の仕様「2 回押し(ダブルクリック)・試用版」: **承認済み・実装済み、実機未確認**(2026-11-09 に人と決めて承認。末尾の節。上の節も合わせて直した)。同日、位相の入力は標準の機能にし、初期値を PC 0° / 75°、CR 140° / 250° に更新(人の指示)
- 追加の仕様「調整操作の記録(学習モード)」(タッチパネルで操作を記録し、AI 学習用の測定 → 操作 → 測定の対を貯める。通常モードは変えない): **承認済み・PC 側は実装済み、実機未確認**(2026-11-09 に人と決めて承認。同日、PC 側(モード選択・パネルの取り決め・台帳・停止と再試行)と模擬テスト 6 グループを実装。保存先は雛形と同じフォルダー、xdt は日時_側の名前に決定。タッチパネルのスケッチは型番待ち → 2026-11-13 に版 1 を作った。ビルドのみ確認)。別文書 [SPEC_調整操作の記録.md](SPEC_調整操作の記録.md)

## 目的

AS100-201 の測定で、人が WF1973 の位相合わせと WAVE LOGGER の開始・停止を手で行っていた作業を、治具のスイッチだけでできるようにする。

## 使う機器

| 機器 | 役割 | 接続 | 使う wrapper |
|---|---|---|---|
| Arduino(UNO R4 Minima 等、スケッチ `firmware/ArduinoSwitchAndReadyLed`) | スイッチ 4 つ(PC_go・CR_go・F8・sw4)と READY LED | USB シリアル(COM ポートを自動で探す) | `Wrappers/Arduino`(取り決めはアプリの `As100201ArduinoProtocol`) |
| NF WF1973 | 連続出力(三角波)を、PC / CR の位相で出し直す | USB(VISA) | `Wrappers/Instruments` の `Wf1973ContinuousSession` |
| KEYENCE NR-500 / NR-X | データロガー。測定の開始・停止 | **USB だけ**。旧 WAVE LOGGER / WAVE LOGGER X(両方入っていれば画面で選ぶ。旧で本体が見つからなければ X に切り替えて NR-500 → NR-X の順に探す) | `Wrappers/WaveLogger.Automation`(`Lifecycle = ReferenceOnly`)、`Wrappers/Common` の `Nr500Connection` |

- NR-X の Wi-Fi は使わない(移植で変えたこと 1)。SSID・IP の置き場は要らない
- Excel・ファイルの保存は使わない。測定データの保存は LOGGER 側の設定に従う

## 入力

- 雛形(xdt / ydt): 人が画面へ 1 件ドラッグする。アプリには同梱しない。LOGGER の `OpenFile` が開ければよい
- 設定値(コードの定数。`As100201/As100201WaveformSettings.cs`): 振幅 10.2Vpp、周波数 0.02Hz、オフセット 0V、波形の形 = 三角波(対称 50%)
- 位相と 2 回押しの待ち時間: 画面で入力し、設定ファイルに残す(末尾の節)。**位相の入力は標準の機能**(2026-11-09 人の指示。試用版だけにしない)。初期値は PC 0° / 75°、CR 140° / 250°(1 回押し / 2 回押し、2026-11-09 人の指示で更新)、0.25 秒

## 出力

- WF1973 の出力、LOGGER の測定(保存は LOGGER の設定)
- 画面のログ。異常があったときは、直近 1 分の記録ごと `Logs\ArduinoIncident_*.log`(exe の隣。書けなければ `%LOCALAPPDATA%\AS100201SwitchController\Logs`)。復旧後 30 秒まで同じファイル。自動削除なし

## 手順

1. 起動すると接続確認(Arduino の確認と、WF1973・LOGGER/NR 本体の確認を並行)。「確認」ボタンでやり直せる
   - WF1973: 出力 OFF → 三角波(RAMP・対称 50%)→ オフセット 0V → バースト OFF → `*OPC?` で設定完了を確かめる
   - WF1973 が接続済みのときの「確認」: `*IDN?` で生存確認したあと、**波形の形(三角波)だけ**を送り直す(`*OPC?` で確認)。出力の ON / OFF・振幅・オフセット・位相は変えない(次の PC_go / CR_go で送る)。動作中に別のアプリや前面パネルで形を変えられても、「確認」を押せば戻る
   - LOGGER: COM で起動・初期化し、NR 本体を USB で確認
2. 雛形をドロップ → LOGGER で開く → READY LED 点灯 → LOGGER を前面に出す。それまではアプリを最前面に保つ
3. スイッチ
   - PC_go / CR_go: 1 回押しは離してから待ち時間後、2 回押しは 2 回目を押した瞬間に、それぞれの位相で出し直す(末尾の節)。出し直しは 振幅・位相・周波数 → オフセット → 位相の初期化(`:SOURce:PHASe:INITiate`)→ 初回だけ出力 ON。出力中は OFF にしない。コマンドの間に次の押下が来たら残りを送らず、最後の押下の位相でやり直す。**波形の形は押すたびには送らない**(出力中に形を送ったときの動きを確かめていないため。形は接続時と「確認」で送る)
   - F8(と画面の「測定開始（確認用）」): LOGGER が開始できる状態なら Start を 1 回。測定中などは開始しない
   - sw4: LOGGER へ Stop(状態が読めなくても送る)
4. 5 秒ごとに WF1973 の `*IDN?` と NR 本体の `GetUnitInfo` で生存確認

## 異常時

- 機器が見つからない: 接続確認で全機器の失敗理由をまとめて表示。READY LED は点かず、スイッチは受け付けない
- Arduino の定期応答(250ms ごと)が 1 秒止まる: 操作を受け付けない。3 秒止まる・切断: 2 秒おきに再接続を試す。復旧後 1 秒は操作を捨てる。切断前・復旧前の押下は実行しない(押し直す)
- Arduino だけの切断では、WF1973 の出力と LOGGER の測定を変えない。READY LED は PC から消せなくても、Arduino が最後の READY_ON から 3 秒で消す
- WF1973 / NR 本体の生存確認に失敗: その機器を未接続にして READY LED を消す。「確認」でやり直す
- LOGGER 側でファイルを閉じた: 雛形の登録を外す(再登録が要る)
- スイッチの処理に失敗: ログと最前面のメッセージボックス
- 終了時: READY LED を消し、Arduino・WF1973 を閉じ、LOGGER は止めずに COM の参照だけ外す(`ReferenceOnly`)

## 移植で変えたこと(2026-11-04、人の指示)

1. **NR 本体は USB だけにした**。移植前は画面で USB / Wi-Fi を選べ、NR-X の Wi-Fi プロファイル(`NRX_E8FDF803634C`、192.168.100.100:24682)をアプリの設定クラスに持っていた。接続方式の選択・Wi-Fi プロファイルの選択・「元のWi-Fiへ戻す」ボタン・終了時の Wi-Fi の復帰を外した。Wi-Fi が要るようになったら、移植前のコード(`As100201ConnectionSettings.cs`、`MainForm.Connections.cs` の Wi-Fi 分岐)と `docs/capabilities.md`「NR-X を Wi-Fi で使うとき」を見て足し直す
2. **接続時に WF1973 の波形の形(三角波・対称 50%)を送るようにした**。移植前は形を送らず本体の設定のまま出していた。移植の実機確認で、直前に AS110NoiseTest が DC にした WF1973 では PC_go / CR_go を押しても DC のままだったため。同じ WF1973 を別のアプリで使った後でも正しく出る。wrapper に `Wf1973ContinuousSession.Connect(GeneratorWaveform)` を足した(既存の `Connect()` の動きは変えていない)。接続済みのときの「確認」でも形だけ送り直す(`SetWaveform`、同日追加)

## 細部

- スイッチ名と Arduino のピン: D1 = READY LED、D2/D3 = F8 の LED 給電 / 入力、D4/D5 = sw4、D6/D7 = CR_go、D8/D9 = PC_go。チャタリング対策 30ms(スケッチ)
- 確認文字列: PC → `AS100201_PING`、Arduino → `AS100201_READY:2`(2026-11-09 に版 2。版 1 は接続エラー。末尾の節)。定期応答 `DIAG_FRAME:<連番>:<millis>`、起動通知 `DIAG_BOOT:1`
- アプリ固有の異常種別: `HEARTBEAT_STALE`、`FRAME_GAP`、`PROTOCOL_RECOVERY`
- LOGGER の開始は毎回 Start(トリガ・状態待ち・再試行なし)。開始できる状態は `GetState` が 1・11 のとき。開始直後 500ms は状態を読まない
- 出力は 10.2Vpp・オフセット 0V で −5.1〜+5.1V。**負の電圧は問題ない**(2026-11-04、人の確認)
- 位相を変えて出し直すと段差が 2 回出る(位相の値を書き換えた時点でその差だけずれ、約 80ms 後に位相の初期化で設定の位相からやり直す。`Wrappers/Instruments/docs/WF1973実機確認.md`)。**使用上の問題はないので、このままにする**(2026-11-04、人の確認)。出力を一度 OFF にすれば段差は 1 回になるが 0V の切れ目が入る、などの対策の候補は検討だけした
  - 2026-11-09: 記録中に PC_go / CR_go を押すと、LOGGER の XY 画面に跳びの前後を結ぶ線が出て見にくい、と分かった。実機で確かめたところ、WF1973 では段差を 1 回にできず(送り方を変えても間が約 8ms 残る)、LOGGER の XY 画面にも線を描かない設定は無い(`Wrappers/Instruments/docs/WF1973実機確認.md`「追記: 連続の出し直しの段差を減らせるか」)。押してから測定開始すれば線は出ないが、記録中に押す使い方のため当てはまらない。候補(送り方を変えて間を約 9ms にする、記録中に押したら測定をやり直す、保存後に跳びの線を描かない XY 図で見るツール)を示し、**人の判断で今のままにした**
- 波形の形は三角波(対称 50%)で固定(人の回答)。正弦波などが要るときは `GeneratorWaveform` に足す(wrapper の追加)

## 追加: 2 回押し(ダブルクリック)・試用版(2026-11-09、承認済み)

人と選択肢を見て決め、同日承認された内容。実装済み・実機未確認(確認した範囲は `Apps/AS100201SwitchController/README.md`「2 回押し」)。

### 目的

PC_go / CR_go を素早く 2 回押したとき、1 回押しとは別の位相で WF1973 を出し直せるようにする。試用版なので、待ち時間と位相を画面で変えながら使い、使い心地と値を決める。**位相を画面で変えられるのは便利なので、試用版だけにせず標準の機能にする**(同日、人の指示。当初は「ゆくゆくは固定値」の予定だった)。2 回押しそのもの(待ち時間を含む)は試用中。

### 決めたこと

| 項目 | 決めた内容 | ほかの選択肢(選ばなかった理由・結果) |
|---|---|---|
| 2 回押しを付けるボタン | **PC_go・CR_go だけ** | F8・sw4 の 2 回押しの機能は未定なので、今は付けない。F8・sw4 は今どおり押した瞬間に開始・停止し、続けて押せば今どおり 2 回動く。機能が決まったら付ける(その時から F8・sw4 の 1 回押しにも待ちが入る) |
| 2 回押しの機能 | PC_go: **位相 75°** で出し直す。CR_go: **位相 200°**(試用後に 250° へ更新)で出し直す。周波数・振幅・オフセット・波形の形は 1 回押しと同じ(人の回答。値は調整しながら変える) | — |
| 1 回押しを待たせるか | **待たせる**。2 回押しでないと分かってから、1 回押しの位相で出し直す。出し直しは 1 回押しか 2 回押しの位相のどちらか 1 回だけ | 待たせない(1 回目ですぐ 1 回押しの位相、2 回目で 2 回押しの位相に出し直し直す)と、2 回押しのとき波形に 1 回押しの位相の出し直しが短く入り、段差が増えてロガーにも残る |
| 待ち時間の測り方 | **1 回目を離してから**測る。離してから待ち時間以内に同じボタンを押したら 2 回押し。離してから待ち時間が過ぎたら 1 回押し | 押してから測る(初期案 0.35 秒)と、離してからの待ちが押していた長さで変わる。離してから測ると、体感の待ち(離してから動くまで)が設定値そのものになり調整しやすい。待ち自体はどちらも同じくらい(人の期待「体感が短くならないか」への回答) |
| 待ち時間 | 初期値 **0.25 秒**。画面で変える | 固定にすると調整のたびに書き込み直し・発行し直しが要る |
| 長押し方式 | **入れない**。2 回押しだけ試す(人の回答「長押しはイメージがつかない」) | 長押しも試したくなったら別に作る(スケッチの書き込み直しがもう 1 回要る) |
| 3 回以上続けて押したとき | **2 回押し 1 回として扱う**。2 回目で出し直し、その後の押下(前に離してから待ち時間以内のもの)は捨ててログにだけ残す。待ち時間が空いたら次は新しい 1 回目 | 3 回目を新しい 1 回目にすると、押しすぎたとき最後の位相が 1 回押しの位相に変わる |
| 待ち中に別のボタンを押したとき | **待っている方を先に動かす**(押した順に動く)。例: PC_go → F8 なら PC の 1 回押しの位相に出し直してから測定開始。PC_go → CR_go なら PC の 1 回押しの位相に出し直し、CR_go は新しく待ち始める(最後は CR の位相) | PC↔CR だけ待っている方を捨てる案は、段差が 1 回減るが、押したのに動かない場合ができる |
| 判定する場所 | **Arduino(スケッチ)** で判定し、結果だけをアプリへ送る | アプリで判定すると、USB や PC の遅れで判定がぶれる。Arduino ならミリ秒の精度で測れる。配線と共通部品(`Wrappers/Arduino`)は変えないので、ほかのアプリに影響しない |
| 古いスケッチをつないだとき | **接続エラーにする**。接続確認の失敗理由に「Arduino のスケッチが古い(版 1)。`firmware/ArduinoSwitchAndReadyLed` を書き込み直してください」と出し、READY LED は点かずスイッチも受け付けない | 1 回押しだけで動かす案は、切り分けの作りと確認が増え、書き込み忘れに気づきにくい |

### 画面

- 入力欄を足す(値を入れるとすぐ次の押下から効く)。位相の入力欄は標準の機能、待ち時間の入力欄は 2 回押しと一緒に試用中

  | 入力欄 | 初期値 | 範囲 |
  |---|---|---|
  | 2 回押しの待ち時間(秒) | 0.25 | 0.05〜1.00、0.01 秒刻み |
  | PC_go 1 回押しの位相(°) | 0(当初 15) | 0〜359、1° 刻み |
  | PC_go 2 回押しの位相(°) | 75 | 同上 |
  | CR_go 1 回押しの位相(°) | 140(当初 165) | 同上 |
  | CR_go 2 回押しの位相(°) | 250(当初 200) | 同上 |

  - 位相が整数なのは、WF1973 の部品(`Wf1973ContinuousSession.StartWithPhaseAsync`)が整数 0〜359 を受け付けるため。小数が要るときは部品に関数を足す(全アプリに影響する確認が要る)
  - 「初期値に戻す」ボタンを付ける
  - 待ち時間は Arduino へ送って効かせる(下の「Arduino とのやり取り」)。Arduino が受け取った値を返したら、ログに「2 回押しの待ち時間 0.25 秒を Arduino に反映」と出す。Arduino が未接続なら、つながったときに送る
  - 位相は出し直しのときにアプリが WF1973 へ送るので、次の押下から効く。出し直しの処理中に変えた場合、処理中の分は変える前の値
- 入力した値は **exe の隣の設定ファイルに保存**し、次に起動しても同じ値で始める。書けないときは `%LOCALAPPDATA%\AS100201SwitchController\` に保存する(ログと同じ考え方)。両方にあるときは新しい方を読む。読めない・壊れているときは全部を初期値で、範囲外の項目はその項目だけ初期値で始め、ログに出す。設定ファイルは発行物に入れない(起動時に無ければ初期値)
- 振幅・周波数・オフセット・波形の形は今どおりコードの固定値(画面では変えない)

### Arduino とのやり取り(スケッチの版 2)

| 向き | 文字列 | 意味 |
|---|---|---|
| PC → Arduino | `AS100201_PING` | 確認(今と同じ) |
| Arduino → PC | `AS100201_READY:2` | 確認応答。版 2 = 2 回押し対応。アプリは `AS100201_READY:` で始まる応答の版を見て、2 以外は接続エラー |
| PC → Arduino | `DOUBLE_WAIT_MS:<ミリ秒>` | 2 回押しの待ち時間。接続確認の直後と、画面で変えたときに送る。範囲外は受け付けず前の値のまま。Arduino は起動時 250ms |
| Arduino → PC | `DOUBLE_WAIT_MS_OK:<ミリ秒>` | 受け付けた待ち時間(範囲外のときは今の値を返す) |
| Arduino → PC | `PC_go` / `CR_go` | 1 回押し。**離してから待ち時間が過ぎた時点**(または待ち中に別のボタンが押された時点)で送る |
| Arduino → PC | `PC_go_2` / `CR_go_2` | 2 回押し。2 回目を押した瞬間(チャタリング対策 30ms の確定後)に送る |
| Arduino → PC | `PC_go_EXTRA` / `CR_go_EXTRA` | 2 回押しの後に続けて押された分。アプリはログにだけ残し、何もしない |
| Arduino → PC | `F8` / `sw4` | 今と同じ(押した瞬間)。待ち中の PC_go / CR_go があれば、その 1 回押しを先に送ってから送る |

- 定期応答(`DIAG_FRAME`)・起動通知・READY LED は今と同じ
- 古いアプリ(版 1 だけ受け付ける)に新しいスケッチをつなぐと、確認応答が合わず「Arduino が見つからない」になる。アプリとスケッチは一緒に更新する

### 異常時

- 待ち中に Arduino が切断した・定期応答が止まった: 今と同じく、切断前・復旧前の押下は実行しない(押し直す)。待っていた 1 回押しも実行しない
- アプリは今と同じく、受信から 1 秒以上遅れて処理することになった押下は捨てる(1 回押しは離してから待ち時間後に届くので、この 1 秒は届いてからの遅れだけで数える)
- 出し直しの処理中に次の押下(1 回押し・2 回押しとも)が来たら、今と同じく残りを送らず、最後の押下の位相でやり直す
- READY LED が消えているとき・接続確認が終わっていないときは、今と同じく受け付けない

### ログ

- 「スイッチ PC_go(2 回押し)を受信」「WF1973 出力開始：PC_go 2 回押し(位相 75°)」のように、1 回押しか 2 回押しかと、使った位相を出す
- 捨てた連打は「PC_go の続けての押下を捨てました」

### 変えないこと
