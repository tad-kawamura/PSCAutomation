# AS100201SwitchController 追加仕様: 調整操作の記録(学習モード)

AS100-201 の流量調整で、熟練者が「測定結果を見て何をしたか」を記録し、あとで AI に判断を学習させるためのデータ(測定 → 操作 → 測定の三つ組)を貯める仕組み。既存のスイッチ制御アプリ(`Apps/AS100201SwitchController`)に**学習モード**として足す。

- 状態: **承認済み・PC 側は実装済み・タッチパネルのスケッチは版 3(2026-11-13、横置き・仮レイアウト、ビルドのみ)・実機未確認**(2026-11-09 に人が承認。同日、PC 側を実装し模擬テスト 6 グループを追加(`Apps/AS100201SwitchController/Learning/`、確認した範囲と未確認は `Apps/AS100201SwitchController/README.md`「学習モード」)。保存先は雛形と同じフォルダー、xdt は日時_側の名前に同日決定。タッチパネルは同日 M5Stack Tab5 に決定、スケッチはこれから)。相談で決める項目(「未定」)は同日の 3 回目で全部決まり、同日に承認された。「いずれ決める」の項目は試作しながら決める。2026-11-10 に人の決定で、学習モードは決まった雛形を自動で読み込み、保存先を exe の隣の `学習データ\`(台帳は 1 つ、xdt は日付フォルダー)に変えた(「決めたこと」の「雛形と保存先(2026-11-10 変更)」)。2026-11-13 に人が Tab5 を Wi-Fi(PC に専用の子機)とバッテリーで使うと決め、同日に細部も決まって承認され、PC 側・共通部品(`TcpLineConnection`)・スケッチ版 2 を実装した(ビルドと模擬のみ、実機未確認。「Wi-Fi・バッテリーへの変更」)。同日、人の指示でノズルを方向だけに、スペーサーに厚さと差のページを、パネルに触れたら測定を止めるを足し、スケッチ版 3 にした(「版 3 の変更」、実機未確認)
- 本体の仕様は [SPEC.md](SPEC.md)。この文書は追加分だけを書く
- 「決めたこと」は 2026-11-09 の相談で人が決めた内容(3 回に分けて決めた)。「未定」は人の判断待ち(3 回目でなくなった)。「いずれ決める」は試作しながら決めると人が決めた項目。残っていること全体(仕様決め・機器・実装・確認・学習側)はトピックだけを末尾の「残課題」にまとめた

## 背景と目的

- AS100-201 は圧縮空気を使うノズルフラッパ式の 3 方弁。流量の大きさはノズルとフラッパの距離、特性の傾きはアマチュアとヨークのエアギャップと磁力で決まる。これらが互いに影響するため、調整は熟練者が測定波形を見ながら判断している
- 調整手順(`学習データ/⑩_2025.06.06_SN091-/AS100-201_調整手順.xlsx`、同 `.pptx`。学習データは作業 PC のローカルにあり、リポジトリには入れない)にはおおまかな規則(立ち上がり電流 PC 3.75mA / CR 9.5mA、最大流量の目標、減磁すると立ち上がりが右にずれる、など)があるが、部品の公差で効き方が変わるので「規則はあってないようなもの」(人の説明)
- 過去の測定データ(SN001〜SN154、xdt 約 1,100 本)は結果だけで、**その間に作業者が何をしたかの記録がない**。また**調整中の波形は今は保存していない**(最終結果だけ残している。人の回答)。学習には「操作前の測定」「操作」「操作後の測定」の対が要る
- この追加仕様は、作業者が操作するたびにタッチパネルのボタンを押すだけで、その対が自動で残るようにする。**将来の AI による判断の提案・自動調整は対象外**(データが貯まってから別に決める)

## モード

| 学習モード | 通常モードの動きに加えて、タッチパネルで操作を記録し、測定のたびに xdt を保存し、CSV 台帳に 1 行 1 出来事を追記する。**タッチパネルがつながっていないと動かない**(人の回答「学習モードのときにタッチパネルがつながっていないなら動かなくていい」) |

### 決めたことから決まる作り(AI の整理)

- **PC はアプリで Wi-Fi を切り替えない**。最初の 1 回だけ、Windows で**子機の上で** Tab5 の Wi-Fi に「自動的に接続」で登録する(Windows の Wi-Fi の登録はアダプターごと)。内蔵の Wi-Fi が Tab5 に、子機が社内 Wi-Fi に自動でつながらないよう、それぞれの「自動的に接続」を外す。NR-X は USB のままなので、Wi-Fi の切替部品(`SingleAdapterWifiManager`)は使わない
- **Tab5 が待ち受け、PC が Tab5 の決まった IP・ポートへ接続しに行く**。PC が待ち受けないので、Windows のファイアウォールに例外を足さなくてよい。Tab5 の親機の IP は固定(ESP32 の親機の既定は 192.168.4.1。社内 LAN と同じ範囲にならないことを確かめる)
- **やり取りの文字は版 1 のまま**(「タッチパネルとのやり取り」)。運ぶ道が USB シリアルからネットワーク(TCP)に変わるだけ。Tab5 は COM ポートの総当たりの対象から外れ、ポートを開いたときのリセット待ち(1.7 秒)も要らなくなる
- **PC 側に部品を足す**: ネットワークで行単位のテキストをやり取りし、定期応答の見張り・再接続を `ArduinoConnection` と同じ作りで行う部品。機器との通信なので共通部品(`Wrappers/`)に足す。**着手前に人へ「全アプリに影響する」確認を取る**(既存のアプリは書き換えない)。上の「変えないこと」の「要る部品はすべて既存のもの」は、この変更が承認されたら改める
- **電池切れ・Wi-Fi の途切れは、今の「通信が途切れた」と同じ扱い**(READY LED を消し、操作ボタンと PC_go / CR_go / F8 を受け付けず、sw4 だけ受け付ける)。記録漏れは起きない
- **USB と Wi-Fi の両方を残す**ので、接続確認・定期応答の見張り・再接続は 2 通りになる。PC 側は今の COM ポートの総当たり(`ArduinoConnection`)を残したまま、Wi-Fi の確認を足す。Tab5 側は、PC から確認文字列(`AS100201_PANEL_PING`)が届いた道を「今の道」とし、操作の行・定期応答はその道だけに送る(同じ操作が 2 本の道で二重に記録されないようにする)。両方つながっているときは USB を使う(下の「決めたこと(2026-11-13、2 回目)」)
- 子機は **2.4GHz 対応・Windows 11 対応**のものにする(Tab5 の無線用チップ ESP32-C6 は 2.4GHz)
- 電池のもちは公式の目安で約 6 時間(画面の明るさ 50%・Wi-Fi 常時オン)。丸 1 日はもたない見込み。充電は Tab5 の電源が入っているときに USB-C から
- **Tab5 の Wi-Fi は未確認**。Wi-Fi は無線用チップ(ESP32-C6)を経由し、Arduino の版によって動かない報告がある(arduino-esp32 の issue #11404、3.2.0)。この PC の esp32 3.3.12 で動くかを最初に確かめる

### 決めたこと(2026-11-13、2 回目)

| 項目 | 決めた内容 | ほかの選択肢(選ばなかった理由) |
|---|---|---|
| 両方つながっているときにどちらを使うか | **USB を使う**(人の決定)。ケーブルが挿さっていれば安定した USB、Wi-Fi は抜いたときの控え | Wi-Fi を優先(充電のために挿していても Wi-Fi のまま)/ 先に見つかった方(どちらになるか毎回変わりうる) |
| 使っている道が切れたとき | **もう一方の道へ自動で移る**(人の決定)。移る間は今の「途切れた」と同じく操作を受け付けない | 同じ道の再接続だけ待つ |
| 途切れの見張りの秒数 | **今と同じ**(人の決定。250ms の定期応答が 1 秒止まれば操作禁止、3 秒で再接続、復旧後 1 秒は操作を捨てる)。Wi-Fi で操作禁止が頻繁に出るようなら実物を見て見直す | Wi-Fi 向けに延ばす / 実物で試して決める |
| PC 側に持つ Tab5 の IP・ポート | **アプリの設定クラスに置く**(人の決定。Tab5 を使うのはこのアプリだけなので、共通の設定ファイルは作らない) | 共通の設定ファイル |
| Tab5 の Wi-Fi の名前(SSID)・パスワード | **スケッチに書く**(AI の仮決め。人の回答は IP の置き場への同意で、SSID の置き場は明示されていないため。異論があれば変える)。変えるときは書き込み直し。リポジトリは Private | 画面で入れて Tab5 に覚えさせる(画面と保存の作りが増える) |
| 電池残量を Tab5 の画面に出すか | **出す**(人の決定)。Tab5 の電圧を測る部品(INA226)で読む | 出さない |
| 残量が少ないとき PC に知らせるか | **PC の画面のログに出す**(人の決定) | Tab5 の画面だけ |
| 1 日もたせ方 | **触っていないときは画面を暗くする**(人の決定) | 電池を 2 個にして交換 / 昼に USB-C で充電 |

### 2 回目の決定から決まる作り(AI の整理・仮決め。異論があれば変える)

- **道の選び方**: 接続確認(「確認」ボタン・起動時)と、使っている道が切れたときに選び直す。USB が見つかれば USB、なければ Wi-Fi。Wi-Fi で使っている最中に USB を挿したときは、すぐには移らず、次に選び直すとき(Wi-Fi が切れた・「確認」を押した)に USB へ移る(測定の途中で COM ポートを探し直さないため。AI の仮決め)。道が変わったら画面のログに出す
- **電池残量のやり取り**: Tab5 は残量(%)・電圧・充電中かを 30 秒ごとに今の道へ送る(例 `BATT:<残量%>:<電圧mV>:<充電中 0/1>`)。PC は残量が **20% 以下**になったとき 1 回だけログに出す(30% を超えたら、次に下がったときにまた出す)。残量の % は電圧から計算する(満充電 約 8.2V、止まる 6.0V。公式の値。実物で合わせる)。数字はいずれも AI の仮決め
- **やり取りの版を 2 に上げる**: 確認応答を `AS100201_PANEL_READY:2` にし、`BATT:` を足す。版 1 の文字はそのまま使う
- **画面を暗くする**: 最後に触ってから **60 秒**で画面を暗くする(消さない。状態は読める明るさ)。暗いときの最初のタッチは画面を明るくするだけで、**ボタンとしては受け付けない**(暗い画面を触って誤って記録しないため)。秒数・明るさは AI の仮決めで、実物で決める
- 画面を暗くするだけで、公式の目安(約 6 時間)からどこまで延びるかは分からない。足りなければ、作業中に USB-C を挿して充電する(挿したあと次に選び直すときに USB の道に移るので、そのまま使える)

## 記録の考え方

- 1 個体の調整は「測定 → 操作 → 測定 → 操作 → … → 測定 → 完了」の列。アプリは **1 行 1 出来事** で CSV 台帳に追記する(出来事 = 測定、操作、完了、取消)
- 三つ組はあとから台帳を読めば組める: ある操作の「前の測定」は直前の測定の行、「後の測定」は直後の測定の行
- PC 側 / CR 側 は、測定の前に押された PC_go / CR_go(今のスイッチ)から分かる。**作業者が側を入力する必要はない**
- 個体の区切り: 完了の行から次の測定の行まで。完了のあとに操作の行が来たら、完了は取り消されたものとして同じ個体が続く
- 立ち上がり電流・最大流量などの特徴量は、**この追加仕様では計算しない**。xdt をそのまま残し、台帳からたどれるようにする。特徴量の定義(立ち上がりをどう読むか)は学習の段階で決めて、別の処理で xdt から計算する(xdt の読み取りは既存の部品 `Wrappers/LoggerFiles` でできる)

## 手順(学習モードの 1 個体の流れ)

1. 起動すると「通常モード / 学習モード」を選ぶ窓が出る。学習モードを選ぶと接続確認にタッチパネルの確認が加わる(見つからなければ動かない)。通常モードを選べば今までどおり
2. 接続確認が通ると、アプリが決まった雛形を自動で読み込む(2026-11-10。それまではドロップ)
3. 作業者が PC_go(または CR_go)→ F8 で測定、見終わったら sw4 で停止(既存)。停止後、アプリは xdt を保存し、測定の行を台帳に足す
4. 作業者が波形を見て判断し、**手を動かす前に**タッチパネルの操作ボタン(と 2 画面目)を押す。LOGGER が測定中なら止めて xdt を保存し、測定の行を足してから、操作の行を足す
5. 作業者が操作(ハンマーで叩く、着減磁する、スペーサーを替える)し、3 に戻る
6. 盲栓確認が OK になったら完了ボタン。アプリは完了の行を足す
7. カバーを付けた測定で NG なら、そのまま操作ボタンを押せば同じ個体の続きとして記録される(完了の取消は自動)

## 異常時

- タッチパネルが見つからない(学習モード): 接続確認の失敗理由に出し、READY LED は点けずスイッチも受け付けない(学習モードは動かない)。通常モードに切り替えれば今までどおり使える
- タッチパネルの通信が途切れた(学習モード): Arduino と同じ作り(250ms ごとの定期応答が 1 秒止まったら操作禁止、3 秒止まる・切断で 2 秒おきに再接続、復旧後 1 秒は操作を捨てる)。途切れている間は READY LED を消し、操作ボタンと PC_go / CR_go / F8 を受け付けない(新しい測定を始めない。記録漏れを作らないため)。sw4 の停止だけは受け付け、xdt の保存と測定の行は残す。測定中の LOGGER と WF1973 の出力は止めない(Arduino の切断と同じ)。復旧したら画面のログに出し、READY LED を戻す
- 決まった雛形が `雛形\` に無い、2 つ以上ある、LOGGER で開けない(学習モード、2026-11-10): ログに理由を出し、雛形待ちのまま(READY LED は点かない)。ドロップすれば使える。接続確認そのものは失敗にしない
- 台帳や xdt に書けない(保存先を作れない、ほかで開かれている): ログと最前面のメッセージボックス(「再試行」ボタン付き)。**保存できるまで止める**: READY LED を消し、PC_go / CR_go / F8 を受け付けず、操作ボタンには `NAK` を返す(台帳に書けないため)。sw4 は受け付ける(止めるものがあれば止める)。保存先を直して「再試行」を押すと、書けなかったものを書き直す(xdt は LOGGER に残っている停止後の波形を `SaveXdt` し直す。次の測定を始めるまで残っている前提で、実機で確かめる)。書けたら READY LED を戻して再開。保存先を直せないときはアプリを終了し、通常モードで起動し直す(記録なしで作業を続ける)
- 測定の行がないのに操作ボタンが押された(測定せずに操作した、起動直後など): そのまま操作の行を足し、備考に「直前の測定なし」と書く。止めない
- 取消ボタンを、取り消せる操作がないときに押した: 何もせずログに出す
- 完了ボタンを続けて 2 回押した: 2 回目は何もせずログに出す

## タッチパネルとのやり取り(案)

Arduino と同じ、行単位のテキスト(115200bps、LF)。文字列はこの追加仕様の専用のものにし、Arduino の文字列とぶつけない(接続確認が COM ポートを総当たりで探すため)。

| 向き | 文字列(案) | 意味 |
|---|---|---|
| PC → パネル | `AS100201_PANEL_PING` | 接続確認 |
| パネル → PC | `AS100201_PANEL_READY:3` | 確認応答(版 3。2026-11-13 に版 1 → 2 → 3 と上げた。確認が届いた道が今の道になる) |
| パネル → PC | `BATT:<残量%>:<電圧mV>:<充電中 0/1>` | 電池残量(版 2 で追加)。30 秒ごとと確認応答の直後。電池なしは残量 -1 |
| パネル → PC | `ACT:MAG` | 着磁 |
| パネル → PC | `ACT:DEMAG:FULL` / `ACT:DEMAG:TAP` | 減磁(しっかり / ちょんちょん) |
| パネル → PC | `ACT:NOZZLE:P:IN` など | ノズル(P / R、IN=近づける / OUT=離す。版 3 で程度をやめた) |
| パネル → PC | `ACT:SPACER:P:UP:0.450:+2` など | スペーサー(P / R、UP=上げる / DOWN=下げる、厚さ=箱の表示 mm、表示との差 μm: `+n` / `-n` / `0`、測っていなければ `NA`。版 3) |
| パネル → PC | `HOLD` | パネルに触れた(版 3)。測定中なら PC が LOGGER を止める。台帳の操作の行にはしない。返事 `ACK:HOLD` はパネルが表示しない |
| パネル → PC | `DONE` | 完了 |
| パネル → PC | `UNDO` | 取消(パネル側で確認「はい」を押したあとに送る) |
| PC → パネル | `ACK:<受け取った文字列>` | 記録できた(パネルは短く表示) |
| PC → パネル | `NAK:<理由>` | 記録できなかった |
| PC → パネル | `STATE:...` | 表示用(何を出すかは「いずれ決める」の表示内容で決める) |
| パネル → PC | `DIAG_FRAME:<連番>:<millis>` | 定期応答(250ms ごと。Arduino と同じ作り) |
| パネル → PC | `DIAG_BOOT:1` | 起動通知(ポートを開いたときのリセットの検知にも使う) |

- 2 画面目の選択と取消の確認はパネルの中で完結させ、確定した 1 行だけを PC に送る(途中の画面遷移は送らない)
- Tab5(ESP32-P4)の USB-C のシリアルは、PC がポートを開いたときにボードがリセットされる場合がある(`ArduinoConnection` は 1.7 秒待ってから確認文字列を送る)。実機で確かめる
