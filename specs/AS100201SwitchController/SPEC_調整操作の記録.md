# AS100201SwitchController 追加仕様: 調整操作の記録(学習モード)

AS100-201 の流量調整で、熟練者が「測定結果を見て何をしたか」を記録し、あとで AI に判断を学習させるためのデータ(測定 → 操作 → 測定の三つ組)を貯める仕組み。既存のスイッチ制御アプリ(`Apps/AS100201SwitchController`)に**学習モード**として足す。

- 状態: **承認済み・PC 側は実装済み・タッチパネルのスケッチは版 4(横置き・仮レイアウト)。USB・Wi-Fi の接続と切り替え、触れたら止まる・選び終わるまで測定できないは実機で確認済み。Wi-Fi だけでの操作から台帳の行・xdt までの通しも 2026-11-19 に実機確認済み**(2026-11-09 に人が承認。同日、PC 側を実装し模擬テスト 6 グループを追加(`Apps/AS100201SwitchController/Learning/`、確認した範囲と未確認は `Apps/AS100201SwitchController/README.md`「学習モード」)。保存先は雛形と同じフォルダー、xdt は日時_側の名前に同日決定。タッチパネルは同日 M5Stack Tab5 に決定、スケッチはこれから)。相談で決める項目(「未定」)は同日の 3 回目で全部決まり、同日に承認された。「いずれ決める」の項目は試作しながら決める。2026-11-10 に人の決定で、学習モードは決まった雛形を自動で読み込み、保存先を exe の隣の `学習データ\`(台帳は 1 つ、xdt は日付フォルダー)に変えた(「決めたこと」の「雛形と保存先(2026-11-10 変更)」)。2026-11-13 に人が Tab5 を Wi-Fi(PC に専用の子機)とバッテリーで使うと決め、同日に細部も決まって承認され、PC 側・共通部品(`TcpLineConnection`)・スケッチ版 2 を実装した(ビルドと模擬のみ、実機未確認。「Wi-Fi・バッテリーへの変更」)。同日、人の指示でノズルを方向だけに、スペーサーに厚さと差のページを、パネルに触れたら測定を止めるを足し、スケッチ版 3 にした(「版 3 の変更」、実機未確認)。同日、選び終わるまで測定を始められないようにし、スケッチ版 4 にした(「版 4 の変更」)。2026-11-17 に Wi-Fi を実機で確かめ、Tab5 の再起動のあと PC の子機が古いつながりに留まる問題を見つけ、人の決定でアプリが子機をつなぎ直すようにした(「子機のつなぎ直し」)
- 本体の仕様は [SPEC.md](SPEC.md)。この文書は追加分だけを書く
- 「決めたこと」は 2026-11-09 の相談で人が決めた内容(3 回に分けて決めた)。「未定」は人の判断待ち(3 回目でなくなった)。「いずれ決める」は試作しながら決めると人が決めた項目。残っていること全体(仕様決め・機器・実装・確認・学習側)はトピックだけを末尾の「残課題」にまとめた

## 背景と目的

- AS100-201 は圧縮空気を使うノズルフラッパ式の 3 方弁。流量の大きさはノズルとフラッパの距離、特性の傾きはアマチュアとヨークのエアギャップと磁力で決まる。これらが互いに影響するため、調整は熟練者が測定波形を見ながら判断している
- 調整手順(`AS100-201_調整手順.xlsx`、同 `.pptx`。元の資料は社内資料なのでリポジトリに入れず、AI のまとめを [調整手順.md](調整手順.md) に書いた(2026-11-26)。調整の基礎にする)にはおおまかな規則(立ち上がり電流 PC 3.75mA / CR 9.5mA、最大流量の目標、減磁すると立ち上がりが右にずれる、など)があるが、部品の公差で効き方が変わるので「規則はあってないようなもの」(人の説明)
- 過去の測定データ(SN001〜SN154、xdt 約 1,100 本)は結果だけで、**その間に作業者が何をしたかの記録がない**。また**調整中の波形は今は保存していない**(最終結果だけ残している。人の回答)。学習には「操作前の測定」「操作」「操作後の測定」の対が要る
- この追加仕様は、作業者が操作するたびにタッチパネルのボタンを押すだけで、その対が自動で残るようにする。**将来の AI による判断の提案・自動調整は対象外**(データが貯まってから別に決める)

## モード

| モード | 内容 |
|---|---|
| 通常モード | 今のアプリの動きそのまま(スイッチで WF1973 の位相出し直しと LOGGER の開始・停止。保存は LOGGER 任せ)。**変えない** |
| 学習モード | 通常モードの動きに加えて、タッチパネルで操作を記録し、測定のたびに xdt を保存し、CSV 台帳に 1 行 1 出来事を追記する。**タッチパネルがつながっていないと動かない**(人の回答「学習モードのときにタッチパネルがつながっていないなら動かなくていい」) |

- モードの切り替え方: **起動時に選ぶ**(2026-11-09、人の回答)。起動すると「通常モード / 学習モード」を選ぶ窓を出し、選んでから接続確認を始める。途中で変えるには再起動する。初期選択は通常モードで、窓を × で閉じたときも通常モード(今までと同じ動きになる。AI の提案、異論があれば変える)
- 学習モード中は、ウィンドウのタイトルと画面上部に「学習モード」と出し、起動時のログにも残す

### 決めたことから決まる作り(AI の整理)

- **PC はアプリで Wi-Fi を切り替えない**(2026-11-17 に、同じ子機を同じ登録でつなぎ直すことだけ足した。下の「子機のつなぎ直し」)。最初の 1 回だけ、Windows で**子機の上で** Tab5 の Wi-Fi に「自動的に接続」で登録する(Windows の Wi-Fi の登録はアダプターごと)。内蔵の Wi-Fi が Tab5 に、子機が社内 Wi-Fi に自動でつながらないよう、それぞれの「自動的に接続」を外す。NR-X は USB のままなので、Wi-Fi の切替部品(`SingleAdapterWifiManager`)は使わない

### 2 回目の決定から決まる作り(AI の整理・仮決め。異論があれば変える)

- **道の選び方**: 接続確認(「確認」ボタン・起動時)と、使っている道が切れたときに選び直す。USB が見つかれば USB、なければ Wi-Fi。Wi-Fi で使っている最中に USB を挿したときは、**空いているとき(測定中でない・パネルで選んでいる途中でない・ほかの処理中でない)に USB へ自動で戻す**(2026-11-18、人の決定。下の「子機のつなぎ直し」の「USB へ自動で戻す」。それまでは AI の仮決めで、次に選び直すとき(Wi-Fi が切れた・「確認」を押した)まで Wi-Fi のままだった)。道が変わったら画面のログに出す
- **電池残量のやり取り**: Tab5 は残量(%)・電圧・充電中かを 30 秒ごとに今の道へ送る(例 `BATT:<残量%>:<電圧mV>:<充電中 0/1>`)。PC は残量が **20% 以下**になったとき 1 回だけログに出す(30% を超えたら、次に下がったときにまた出す)。残量の % は電圧から計算する(満充電 約 8.2V、止まる 6.0V。公式の値。実物で合わせる)。数字はいずれも AI の仮決め
- **やり取りの版を 2 に上げる**: 確認応答を `AS100201_PANEL_READY:2` にし、`BATT:` を足す。版 1 の文字はそのまま使う
- **画面を暗くする**: 最後に触ってから **60 秒**で画面を暗くする(消さない。状態は読める明るさ)。暗いときの最初のタッチは画面を明るくするだけで、**ボタンとしては受け付けない**(暗い画面を触って誤って記録しないため)。秒数・明るさは AI の仮決めで、実物で決める
  - 実機で見た結果(2026-11-25、人): 60 秒で暗くする指示は出ている(明るさ 24 にした)。ただし見た目はほとんど暗くならない。明るさを 16・8・4・2・1 と下げてもあまり変わらず、0 だけは真っ暗になった。明るさは 22 番ピンの PWM(M5GFX の既定で 44100 回/秒)で変えており、0 で消えるので、ピンは明るさにつながっている。点滅が速すぎて、短い点灯でもほぼ点けっぱなしと同じに見えているのでは、という見立て(未確かめ。PWM の周波数を下げる試しは、作る途中でやめた)
  - 人の決定(2026-11-25): 画面の明暗はここまでにする。スケッチは元のまま(60 秒・明るさ 24)
  - 気になる点: 見た目がほとんど変わらないので、人は暗くなったと気づかずにボタンを押し、その最初のタッチは明るくするだけで記録されない(ただし測定中なら止まる)。実際の作業で困ったら、暗くするのをやめるか、周波数を下げる試しを再開する
- 画面を暗くするだけで、公式の目安(約 6 時間)からどこまで延びるかは分からない。足りなければ、作業中に USB-C を挿して充電する(挿すと空いているときに USB の道へ自動で戻るので、そのまま使える。2026-11-18 から)

### 子機のつなぎ直し(2026-11-17、実機で見つけた問題への対処。人の決定)

- **見つけたこと(実機)**: Tab5 は、PC が USB を開いたとき・USB を抜いたときなどに再起動することがある(`rst:0x17`。DTR を変えても防げなかった)。再起動すると Tab5 の Wi-Fi の親機がやり直しになるが、**PC の子機(BUFFALO WI-U2-150M)は気づかず「接続中・電波 100%」のまま古いつながりに留まり、Tab5 に届かなくなる**。子機を切ってつなぎ直すとすぐ届く。電源ボタンで入れ直すと治っていたのは、親機が長く消えて子機が切れたことに気づくため。版 4 の「USB を抜くと良くない状態になる」(2026-11-13)はこれと、そのとき電池が無く Tab5 の電源が切れたことによる
- **決めたこと(人の決定 B)**: **Wi-Fi で 2 回続けてつながらないとき、アプリが子機だけを切って Tab5 の Wi-Fi の登録(`AS100201_PANEL`)でつなぎ直す**。上の「PC はアプリで Wi-Fi を切り替えない」を少し変える(接続先は変えず、同じ子機を同じ登録でつなぎ直すだけ。内蔵の Wi-Fi・社内ネットには触らない)。選ばなかった案: Tab5 が起動時に親機を長く止めて子機に気づかせる(何秒止めればよいかが子機しだいで確実でなく、USB で開くたびの再起動のたびに長く待つ)
- 作り(AI、2026-11-17): `Learning/As100201PanelWifiRefresh.cs`
  - 子機は**アダプターの名前(「Wi-Fi 2」は PC ごとに変わる)ではなく、登録 `As100201PanelNetworkSettings.WifiProfileName` を持つアダプター**として探す。登録を持つアダプターが 2 台以上なら、内蔵を切らないよう、つなぎ直さずログに理由を出す。登録が無ければ理由を出す
  - Windows の Wi-Fi の仕組み(wlanapi)を直接使う(`netsh` の表示は Windows の言語で変わるため)。保存済みの登録だけを使い、パスワードは扱わない。管理者の権限は要らない
  - つなぎ直しは**裏で進め、見張りを止めない**(見張りは Arduino・LOGGER と同じ流れで回るため)。つなぎ直している間の確認はすぐ失敗にし、終わったあとの次の確認で Wi-Fi に移る。接続は 20 秒の間 4 秒おきに頼み直す(Tab5 の再起動中に 1 回だけ頼むと Windows がすぐ諦め、約 30 秒切れたままだった)。**30 秒に 1 回まで**(Tab5 の電源が切れているときに繰り返さない)。つないだ・つなげなかったことは画面のログと異常ログ(`PANEL_WIFI_REFRESH`)に出す
- スケッチ(版 4 のまま): 起動のたびに Wi-Fi を始める前に無線用チップ ESP32-C6 の電源を入れ直す(I/O 拡張 0x44 の P0、0.3 秒切る)。本体だけの再起動で C6 が前の状態のまま残らないように入れた(PC 側の原因が分かる前の対処。害はないので残す)。USB の確認に答えたあとに診断の行 `DIAG_WIFI:started=<0/1>:pwr=<切る・入れる・読み返し>:start_ms=<ms>:up_ms=<ms>` を送る(PC は知らない行として異常ログに残すだけ)
- **実機で確かめたこと(2026-11-17)**: 子機で Tab5 の親機に自動接続し、内蔵の社内 Wi-Fi・インターネットはそのまま使える。USB なしで起動すると Wi-Fi で約 0.3〜5 秒でつながる。USB でつながっているときに USB を抜くと、**今の作りで 3 回とも 8〜11 秒で子機をつなぎ直して Wi-Fi に自動で移った**(前の作り(つなぎ直しを待つ形)では 3 回が 5〜7 秒、1 回は子機が約 30 秒つながらず、これを受けて頼み直しと裏で進める形にした)。Tab5 の電源を約 2 分切ると、つなぎ直しは約 30 秒おきに失敗を記録し、電源を入れると人の手を介さずつながり直した
- Wi-Fi だけでの通し(2026-11-19、実機): Tab5 を電池・Wi-Fi だけにし、WF1973・NR-500・Arduino をつないで、押した行 → 測定の行(sw4)→ 操作の行、測定中にパネルに触れて止める → 測定の行(操作ボタン)→ 操作の行、xdt・取り込みの CSV まで通った(README「Tab5 を Wi-Fi・電池で使う」)
- 未確認: Wi-Fi で長く使っている最中の定期応答の止まりの出方、画面を暗くする・電池のもち
- **切り替えを速くする(2026-11-17 夕、人の決定)**: 人「5 秒くらいかかっている、もっと早くならないか」。測ると USB を抜いてから 8〜11 秒で、子機が古いつながりになるのは抜いたときではなく、アプリが起動時に USB を開いて Tab5 が再起動したときだった(抜いたとき Tab5 は再起動していない。`DIAG_FRAME` の起動からの ms で確認)。人が選んだのは次の 3 つ
  - B: Wi-Fi の TCP の接続待ちを 3 秒 → 1 秒(`As100201PanelNetworkSettings.ConnectTimeout`。共通部品は変えず、アプリから設定する)
  - C: 使っていた USB が切れたら、Wi-Fi の失敗を待たずにすぐ子機をつなぎ直す(「2 回続けて」は USB が切れたときだけ待たない)。Wi-Fi の確認はつなぎ直しの終わりを最大 3 秒待ち、終われば同じ確認の中で TCP につなぐ。「切れた」は、切断の知らせのほか、最後につながっていた USB の確認が失敗したときにも 1 回だけ判断する(見張りが先にポートを閉じて知らせが届かないことが実機であった)

  - 選ばなかった案: A(USB で使っている間も ping で Wi-Fi を見張り、古くなっていたら先につなぎ直しておく。抜いて約 0.5 秒の見込みだが、新しい見張りが増える)

#### 作り(2026-11-27 実装。AI が決めた細部を含む)

**やり取り(版 6)**: パネル → PC は `PHASE:PC1|PC2|CR1|CR2`、`VALVE`、`REMEASURE`、`STOP`、`ACT:NOZZLE:P|R:START|DONE|CANCEL`(ノズルの節の案 `ACT:NOZZLE:P:START` などと同じ。測り直すは `REMEASURE`)、操作・完了・取消は版 5 と同じ。画面の位置に `NOZZLE:P` / `NOZZLE:R` を足した(ノズルの画面。測定できる)。`HOLD` とノズルの `IN` / `OUT` はなくした。PC → パネルに次を足した(AI の決め)

- `STATE:<L|N>:<測っている位相 PC1 など、止まっていれば ->:<処理中 0|1>:<位相 4 つ>`: 測っている位相の枠、処理中にボタンを押せなくする、ボタンの名前の位相、通常モードの画面。画面の位置が届くたび(1 秒ごと)と変わったときに送る
- `GOTO:NOZZLE:P|R`: 「合わせた」を取り消したとき、パネルを合わせている画面へ戻す
- `MSG:<E|W|I>:<文>`: 後から分かった知らせ(LOGGER が止まりきらず測り始められなかった、など)

**決めた細部(AI の仮決め。実物で使って変えることがある)**

- PC / CR・バルブを動かす・測り直す・測定停止の `ACK` は受け付けた時点で返し、Tab5 の下の帯には出さない(測り直しは LOGGER が止まりきるのを待つので数秒かかり、返事待ち 2 秒を超えるため)。測っているかは `STATE:` の枠で分かる
- 止めてから測り直すまでの間(PC / CR で区切る・測り直す)は「処理中」にし、Tab5 のボタンと PC の画面のボタンを押せなくする。PC の「測定停止」だけは押せて、処理を止める。20 秒たっても止まりきらなければ新しく測らず、Tab5 に知らせる
- 停止のきっかけ(台帳の列)の言葉: `PC / CR`、`バルブを動かす`、`測り直す`、`合わせた`、`戻る`、`PC の測定停止`、操作・完了・取消で止めたときは今までどおり `操作ボタン`
- 台帳の「側」: 2 回押しをやめたので、位相2 は `PC（位相2）` / `CR（位相2）`(版 5 までは `PC（2回押し）`)。xdt の名前の `PC2` / `CR2` はそのまま。位相の設定ファイルの項目名も変えない

### ノズルは「立ち上がりを合わせる」にする(2026-11-26 承認)

- ノズル P 側(R 側も同じ)を選ぶ → 人がカンカン棒で立ち上がりを合わせる(その間は記録しておく)→ 合わせ終わったら「P 側の立ち上がりを合わせた」を押して、その作業の完了を記録する

**Tab5**

## 記録の考え方

- 1 個体の調整は「測定 → 操作 → 測定 → 操作 → … → 測定 → 完了」の列。アプリは **1 行 1 出来事** で CSV 台帳に追記する(出来事 = 測定、操作、完了、取消)
- 三つ組はあとから台帳を読めば組める: ある操作の「前の測定」は直前の測定の行、「後の測定」は直後の測定の行
- PC 側 / CR 側 は、測定の前に押された PC_go / CR_go(今のスイッチ)から分かる。**作業者が側を入力する必要はない**
- 個体の区切り: 完了の行から次の測定の行まで。完了のあとに操作の行が来たら、完了は取り消されたものとして同じ個体が続く
- 立ち上がり電流・最大流量などの特徴量は、**この追加仕様では計算しない**。xdt をそのまま残し、台帳からたどれるようにする。特徴量の定義(立ち上がりをどう読むか)は学習の段階で決めて、別の処理で xdt から計算する(xdt の読み取りは既存の部品 `Wrappers/LoggerFiles` でできる)

## 手順(学習モードの 1 個体の流れ)

1. 起動すると「通常モード / 学習モード」を選ぶ窓が出る。学習モードを選ぶと接続確認にタッチパネルの確認が加わる(見つからなければ動かない)。通常モードを選べば今までどおり
2. 接続確認が通ると、アプリが決まった雛形を自動で読み込む(2026-11-10。それまではドロップ)
3. 作業者が PC_go(または CR_go)→ F8 で測定、見終わったら sw4 で停止(既存)。停止後、アプリは xdt を保存し、測定の行を台帳に足す
4. 作業者が波形を見て判断し、**手を動かす前に**タッチパネルの操作ボタン(と 2 画面目)を押す。LOGGER が測定中なら止めて xdt を保存し、測定の行を足してから、操作の行を足す
5. 作業者が操作(ハンマーで叩く、着減磁する、スペーサーを替える)し、3 に戻る
6. 盲栓確認が OK になったら完了ボタン。アプリは完了の行を足す
7. カバーを付けた測定で NG なら、そのまま操作ボタンを押せば同じ個体の続きとして記録される(完了の取消は自動)

## 異常時

- タッチパネルが見つからない(学習モード): 接続確認の失敗理由に出し、READY LED は点けずスイッチも受け付けない(学習モードは動かない)。通常モードに切り替えれば今までどおり使える
- タッチパネルの通信が途切れた(学習モード): Arduino と同じ作り(250ms ごとの定期応答が 1 秒止まったら操作禁止、3 秒止まる・切断で 2 秒おきに再接続、復旧後 1 秒は操作を捨てる)。途切れている間は READY LED を消し、操作ボタンと PC_go / CR_go / F8 を受け付けない(新しい測定を始めない。記録漏れを作らないため)。sw4 の停止だけは受け付け、xdt の保存と測定の行は残す。測定中の LOGGER と WF1973 の出力は止めない(Arduino の切断と同じ)。復旧したら画面のログに出し、READY LED を戻す
- 決まった雛形が `雛形\` に無い、2 つ以上ある、LOGGER で開けない(学習モード、2026-11-10): ログに理由を出し、雛形待ちのまま(READY LED は点かない)。ドロップすれば使える。接続確認そのものは失敗にしない
- 台帳や xdt に書けない(保存先を作れない、ほかで開かれている): ログと最前面のメッセージボックス(「再試行」ボタン付き)。**保存できるまで止める**: READY LED を消し、PC_go / CR_go / F8 を受け付けず、操作ボタンには `NAK` を返す(台帳に書けないため)。sw4 は受け付ける(止めるものがあれば止める)。保存先を直して「再試行」を押すと、書けなかったものを書き直す(xdt は LOGGER に残っている停止後の波形を `SaveXdt` し直す。次の測定を始めるまで残っている前提で、実機で確かめる)。書けたら READY LED を戻して再開。保存先を直せないときはアプリを終了し、通常モードで起動し直す(記録なしで作業を続ける)
- 測定の行がないのに操作ボタンが押された(測定せずに操作した、起動直後など): そのまま操作の行を足し、備考に「直前の測定なし」と書く。止めない
- 取消ボタンを、取り消せる操作がないときに押した: 何もせずログに出す
- 完了ボタンを続けて 2 回押した: 2 回目は何もせずログに出す

## タッチパネルとのやり取り(案)

Arduino と同じ、行単位のテキスト(115200bps、LF)。文字列はこの追加仕様の専用のものにし、Arduino の文字列とぶつけない(接続確認が COM ポートを総当たりで探すため)。

| 向き | 文字列(案) | 意味 |
|---|---|---|
| PC → パネル | `AS100201_PANEL_PING` | 接続確認 |
| パネル → PC | `AS100201_PANEL_READY:5` | 確認応答(版 5。2026-11-13 に版 1 → 2 → 3 → 4、2026-11-26 に 5 へ上げた。確認が届いた道が今の道になる) |
| パネル → PC | `BATT:<残量%>:<電圧mV>:<充電中 0/1>` | 電池残量(版 2 で追加)。30 秒ごとと確認応答の直後。電池なしは残量 -1 |
| パネル → PC | `ACT:MAG` | 着磁 |
| パネル → PC | `ACT:DEMAG:FULL` / `ACT:DEMAG:TAP` | 減磁(しっかり / ちょんちょん) |
| パネル → PC | `ACT:NOZZLE:P:IN` など | ノズル(P / R、IN=近づける / OUT=離す。版 3 で程度をやめた) |
| パネル → PC | `ACT:SPACER:P:UP:0.450:+2` など | スペーサー(P / R、UP=上げる / DOWN=下げる、厚さ=箱の表示 mm、表示との差 μm: `+n` / `-n` / `0`、測っていなければ `NA`。版 3) |
| パネル → PC | `HOLD` | パネルに触れた(版 3)。測定中なら PC が LOGGER を止める。台帳の操作の行にはしない。返事 `ACK:HOLD` はパネルが表示しない |
| パネル → PC | `SELECT` / `HOME` | 操作を選んでいる途中(2 画面目以降)/ 1 画面目(版 4)。ページを移ったとき・1 秒ごと・確認応答の直後に送る。SELECT の間 PC は測定を始めない。返事なし |
| パネル → PC | `DONE` | 完了 |
| パネル → PC | `ACT:…:MOVED` | 操作の行の後ろの印(版 5)。測定中に動かした。どの操作にも付く(例 `ACT:MAG:MOVED`) |
| パネル → PC | `UNDO` | 取消(パネル側で確認「はい」を押したあとに送る)。版 5 から直前の測定も対象 |
| PC → パネル | `ACK:<受け取った文字列>` | 記録できた(パネルは短く表示) |
| PC → パネル | `NAK:<理由>` | 記録できなかった |
| PC → パネル | `LAST:M:<説明>` / `LAST:O:<説明>` / `LAST:` | 直前の記録(取消の対象。測定 / 操作 / なし。版 5)。台帳に書くたびと、`SELECT` / `HOME` を受けるたびに送る。返事なし |
| PC → パネル | `STATE:...` | 表示用(何を出すかは「いずれ決める」の表示内容で決める) |
| パネル → PC | `DIAG_FRAME:<連番>:<millis>` | 定期応答(250ms ごと。Arduino と同じ作り) |
| パネル → PC | `DIAG_BOOT:1` | 起動通知(ポートを開いたときのリセットの検知にも使う) |

- 2 画面目の選択と取消の確認はパネルの中で完結させ、確定した 1 行だけを PC に送る(途中の画面遷移は送らない)
- Tab5(ESP32-P4)の USB-C のシリアルは、PC がポートを開いたときにボードがリセットされる場合がある(`ArduinoConnection` は 1.7 秒待ってから確認文字列を送る)。実機で確かめる
