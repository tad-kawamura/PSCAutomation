# AS100201SwitchController

AS100-201 のスイッチ制御・測定アプリ。治具の Arduino のスイッチ操作を受け取り、WF1973 の連続出力(三角波)を位相をそろえて出し直し、KEYENCE WAVE LOGGER の測定開始・停止を行う。

元は GitHub `tad-kawamura/AS100201SwitchController`(`5eb5b6391a82`、2026-10-28)。旧リポジトリは 2026-11-04 にアーカイブした(読み取り専用)。移植前の履歴はそちらで見る。旧リポジトリの README・AGENTS.md の冒頭には、ここへの案内を書いてある(`c8a5e4b`)。旧リポジトリをクローンした PC は、PSCAutomation をクローンし直して作業する。

- 仕様(機器・操作・異常時・移植で変えたこと): [specs/AS100201SwitchController/SPEC.md](../../specs/AS100201SwitchController/SPEC.md)
- Arduino スケッチ: `firmware/ArduinoSwitchAndReadyLed/ArduinoSwitchAndReadyLed.ino`。**版 2**(2026-11-09、PC_go / CR_go の 2 回押しの判定を追加)。**アプリとスケッチは一緒に更新する**: 版 1 のスケッチをこのアプリにつなぐと接続エラー(「スケッチが古い」)、版 2 のスケッチを 2026-11-09 より前のアプリにつなぐと「Arduino が見つからない」になる。書き込みは Arduino IDE で(ボードは UNO R4 Minima)
- タッチパネル(学習モード)のスケッチ: `firmware/Tab5LearningPanel/Tab5LearningPanel.ino`。**版 1**(2026-11-13、横置き・仮レイアウト)。書き込みは下の「タッチパネルのスケッチを書き込む」

## 開く・ビルドする

Visual Studio ではリポジトリのルートの `AS100201SwitchController.slnf` を開く(アプリ・互換テスト・使う wrapper 5 つ)。

```powershell
dotnet build AS100201SwitchController.slnf
```

NI-VISA が入っていない PC ではビルドできない(`Wrappers/Instruments` が `Ivi.Visa.Interop` を参照するため)。

## 操作

| 操作 | 動作 |
|---|---|
| 起動 | まず「通常モード / 学習モード」を選ぶ窓が出る(初期選択は通常。× も通常)。通常モードを選べば今までどおり。次に Arduino・WF1973・LOGGER/NR 本体(USB)を確認する。WF1973 は三角波にする。「確認」ボタンでやり直せる |
| 「確認」(WF1973 が接続済み) | WF1973 の生存確認のあと、波形の形(三角波)だけを送り直す。出力・振幅・位相は変えない(形が DC などになっていたら、これで戻る) |
| 雛形を画面へドロップ | LOGGER で開く。READY LED が点く(学習モードは接続確認のあとに決まった雛形を自動で開くので、ふだんはドロップしない) |
| PC_go / CR_go(1 回押し) | **離してから待ち時間(初期 0.25 秒)後に**、WF1973 を 1 回押しの位相(初期 PC 0° / CR 140°)で出し直す。出力中は OFF にしない。処理中の再押下は最後の押下で上書き |
| PC_go / CR_go(2 回押し) | 1 回目を離してから待ち時間以内にもう一度押すと、2 回目を押した瞬間に 2 回押しの位相(初期 PC 75° / CR 250°)で出し直す。3 回以上続けて押しても 2 回押し 1 回(続きはログだけ)。待ち中に別のボタンを押すと、待っていた 1 回押しを先に動かす |
| 画面の「出し直しの位相」 | 4 つの位相(0〜359°)と 2 回押しの待ち時間(0.05〜1.00 秒)を入力する。位相の入力は標準の機能(2 回押しは試用中)。次の押下から効く。exe の隣の `AS100201SwitchController.settings.json` に残す(書けなければ `%LOCALAPPDATA%\AS100201SwitchController\`)。「初期値に戻す」あり |
| F8 / 「測定開始（確認用）」 | LOGGER の測定開始(毎回 Start)。2 回押しなし(押した瞬間) |
| sw4 | LOGGER の停止。2 回押しなし(押した瞬間) |

NR 本体は **USB だけ**(NR-500 / NR-X)。移植前にあった Wi-Fi の選択と「元のWi-Fiへ戻す」ボタンは外した(SPEC.md)。

## 学習モード(2026-11-09 承認、PC 側は実装済み、実機は一部確認)

仕様は [SPEC_調整操作の記録.md](../../specs/AS100201SwitchController/SPEC_調整操作の記録.md)。熟練者の流量調整を「操作前の測定 → 操作 → 操作後の測定」の三つ組で貯め、ゆくゆく AI に判断を学習させるためのもの。**通常モードの動きは変えていない**(通常モードでは学習モードの部品を作らない)。

### 使い方(学習モード)

1. 起動の窓で「学習モード」を選ぶ(Tab5 なしで試すときは開発用の 3 つ目。下の「Tab5 なしで確かめる」)。タイトルと画面上部に「学習モード」と出る。接続確認に**タッチパネル(M5Stack Tab5、USB シリアル)**が加わり、見つからなければ READY LED は点かずスイッチも受け付けない(通常モードで起動し直せば今までどおり)
2. 接続確認が通ると、exe の隣の `雛形\` にある xdt(`雛形_AS100_201流量調整用_650kPa_0_02Hz_10Vpp.xdt`)を自動で LOGGER に開く(**ドロップ不要**、2026-11-10 人の決定)。`雛形\` に xdt が無い・2 つ以上ある・開けないときは、ログに理由を出して雛形待ちのまま(ドロップすれば使える)。別の雛形を使うときは「雛形を削除」してからドロップする(保存先は変わらない)。「確認」を押し直すと、決まった雛形を開き直す
3. 作業者は今までどおり PC_go / CR_go → F8 → sw4 で測定する。sw4 で止まるたびに、アプリが測定の行を台帳に足し、LOGGER の状態が停止に戻った時点で xdt を保存する(名前は `yyyyMMdd_HHmmss_PC.xdt`。2 回押しの側は `PC2` / `CR2`、位相を出し直していなければ日時だけ、同じ秒は `_2`。2026-11-09 人の決定)

**保存先(2026-11-10 人の決定。それまでは雛形と同じフォルダー)**: exe の隣の `学習データ\`。台帳 `調整記録.csv` はその直下に 1 つ、xdt は日付フォルダーに置く。日付は測定を止めた時刻の日付。フォルダーは最初に書くときにアプリが作る。保存先は雛形に依存しないので、雛形を開く前の操作ボタンも記録する(測定は雛形が無いと始められない)。

```
exe の隣\学習データ\
  調整記録.csv                  ← 台帳は 1 つ(「ファイル」列は 20261110\20261110_133028_PC.xdt のように日付フォルダー付き)
  20261110\
    20261110_133028_PC.xdt
```
4. 手を動かす前にタッチパネルの操作ボタン(着磁・減磁・ノズル P/R・スペーサー P/R、2 画面目で方向・程度)を押す。測定中なら LOGGER を止めて測定の行を書いてから、操作の行を足す。パネルには `ACK:<行>` / `NAK:<理由>` を返す
5. 盲栓確認 OK で「完了」。完了のあとに操作が来たら備考「完了の取消」で同じ個体の続き。「取消」は直前の操作 1 件だけ(測定・完了を挟むと取り消せない)。測定なしの操作は備考「直前の測定なし」

台帳は UTF-8(BOM 付き、Excel でそのまま開ける)、新しいファイルの先頭だけヘッダー行、追記のみ。列: 日時、種類、側、位相、停止のきっかけ、操作、方向、程度、厚さ(未使用)、ファイル、備考。

**押した行(2026-11-12)**: PC_go / CR_go で WF1973 の出し直しが終わるたびに、種類「押した」の行を足す(1 回の記録の中で PC と CR が切り替わっても、あとで区間を切り出せるようにするため。`SPEC_測定中の取り込み.md`「押した瞬間の記録」)。「側」「位相」は測定の行と同じ書き方。「備考」にミリ秒までの時刻、測定中なら F8 からの秒と LOGGER の点数(`点数 1234（xdt の 1235 点目から後）`)、測定していなければ「測定していないとき」。処理中に次の押下で上書きされた押下・出し直しに失敗した押下は書かない。押した行は個体の数え方・取消・「直前の測定なし」に影響しない。書けなければ測定の行と同じく止めて「再試行」。細かい形は試しながら変える。

```
2026-11-12 10:15:03,押した,CR,140,,,,,,,10:15:03.482、F8 から 32.517 秒、点数 3251（xdt の 3252 点目から後）
```

### 異常時(学習モード)

- タッチパネルの定期応答が止まる・切断: Arduino と同じ作り(1 秒で操作禁止、3 秒・切断で 2 秒おきに再接続、復旧後 1 秒は捨てる)。途切れている間は READY LED を消し、PC_go / CR_go / F8 と操作ボタンを受け付けない。**sw4 の停止だけ受け付け**、xdt と測定の行は残す
- 台帳や xdt に書けない: 最前面のメッセージボックス(「再試行」「キャンセル」)。保存できるまで READY LED を消し、PC_go / CR_go / F8 を受け付けず、操作ボタンには `NAK`。測定の行と xdt は覚えておき、「再試行」(メッセージボックス、または画面の「再試行」ボタン)で順に書き直して再開する。操作ボタンは記録されないので、再開後に押し直す

### Tab5 なしで確かめる(開発用:タッチパネルの代わり、2026-11-10)

Tab5 が届く前に、学習モードの PC 側(操作 → 台帳の行、sw4・操作ボタンでの停止と xdt の保存、パネルが途切れたときの受け付け)を実機の LOGGER・WF1973・Arduino で確かめるためのもの。作業者向けではない。

起動の窓で 3 つ目の「学習モード（開発用：タッチパネルの代わりを画面に出す…）」(青い文字)を選ぶ(2026-11-10 人の指摘で起動の窓にも出した。最初は引数だけだったため、ふつうの「学習モード」を選ぶと本物のパネルを探して接続エラーになった)。引数でも起動の窓を飛ばして同じ状態にできる。

```powershell
Apps/AS100201SwitchController/bin/Debug/net9.0-windows/AS100201SwitchController.exe --virtual-panel
```

Visual Studio では起動プロファイル「学習モード（タッチパネルの代わり・開発用）」(`Properties/launchSettings.json`)を選ぶ。発行した exe でも同じ引数で使える。

- タイトルに「（開発用：タッチパネルの代わり）」、帯は青
- 接続確認で COM ポートのタッチパネルは探さず、アプリの中の代わりが確認応答(版 1)と 250ms の定期応答を出す。代わりのボタンは、パネルが確定した 1 行(`ACT:…` / `DONE` / `UNDO`)を送ったのと同じ処理(`As100201PanelProtocol` → 受け付けの決まり → 記録)を通る。**台帳と xdt は本番と同じく exe の隣の `学習データ\` に保存する**(2026-11-10 から。試しの記録を本番と分けたいときは、試し用のフォルダーに exe と `雛形\` をコピーして使う)
- 画面の「タッチパネルの代わり」: 21 通りの行の一覧と「送る」、よく使う「着磁」「完了」「取消」。「パネルへの返事」に `ACK` / `NAK` を出す(ログにも出る)。取消の確認はパネル側の仕事なので、代わりでは確認なしで `UNDO` を送る
- 「定期応答を止める」: USB はつながったまま固まった状態。1 秒で受け付けなくなり、3 秒で再接続を繰り返す
- 「USB を抜いた状態」: 切断。外すと 2 秒おきの再接続で戻る(戻ってから 1 秒は操作を捨てる)
- 代わりで確かめられないこと: Tab5 の COM ポートの総当たり(Arduino と並べて 2 台)、ポートを開いたときのリセット、本物のシリアルの遅れ、タッチの反応、パネルの画面

### タッチパネルとのやり取り

Arduino と同じ 115200bps・LF の行単位。PC → `AS100201_PANEL_PING`、パネル → `AS100201_PANEL_READY:1`(版 1 以外は接続エラー)、`DIAG_FRAME:<連番>:<millis>`(250ms)、`DIAG_BOOT:1`、操作は `ACT:MAG` / `ACT:DEMAG:FULL|TAP` / `ACT:NOZZLE:P|R:IN|OUT:1|2|3` / `ACT:SPACER:P|R:UP|DOWN` / `DONE` / `UNDO`。パネルは **M5Stack Tab5**(ESP32-P4、5 インチ 1280×720、2026-11-09 人の決定)。画面は M5GFX で自前描画(2026-11-10 人の決定)。スケッチは Arduino 向けの `AS100201_PING` を無視すること(接続確認が COM ポートを総当たりで探すため、Arduino の確認文字列がパネルにも届く。逆に Arduino のスケッチは知らない行を無視する)。

### タッチパネルのスケッチを書き込む(2026-11-13)

スケッチは `firmware/Tab5LearningPanel/Tab5LearningPanel.ino`(版 1)。Arduino IDE で開き、ツール メニューを次のようにして書き込む。

| 項目 | 設定 |
|---|---|
| ボード | **M5Tab5**(esp32 by Espressif Systems 3.3 系。この PC は 3.3.12) |
| USB Mode | **Hardware CDC and JTAG** |
| USB CDC On Boot | **Enabled**(これが無いと USB-C から PC に行が届かず、アプリの接続確認でパネルが見つからない) |
| Chip Variant | 既定の「Before v3.00」。書き込み時に esptool が出すチップの版が v3.0 以上なら「v3.00 or newer」 |
| ライブラリ | M5Unified / M5GFX(0.3.0 で確かめた) |

- 書き込めない(ポートが出ない)ときは、リセットボタンを 2 秒ほど長押しして緑の LED が速く点滅する状態にしてから書き込む(M5Stack の手順)
- 上下が逆に見えたら、スケッチの `FLIP_LANDSCAPE` を `true` にして書き込み直す

画面(横置き 1280×720、仮レイアウト。実物で見て直す):

- 上の帯: 「調整記録パネル」と PC とのつながり(赤: USB なし / 黄: アプリの確認待ち・返事待ち / 緑: つながっている)。**アプリの確認(`AS100201_PANEL_PING`)を受けるまでは、送るボタンは灰色で押せない**
- 1 画面目: 左に 6 操作(上段 着磁・ノズル P 側・スペーサー P 側、下段 減磁・ノズル R 側・スペーサー R 側)、右の列に完了(緑)・取消(橙)

**移植の実機確認で見つけて直したこと**: 最初の確認で、PC_go / CR_go を押しても WF1973 が DC のままだった。アプリの送ったコマンド(位相・出力 ON)は正しく、WF1973 本体の「波形の形」が直前に使った AS110NoiseTest の DC のまま残っていたため(移植前のアプリは形を送らず本体の設定を使う作り)。人と相談して、接続時に三角波(対称 50%)を送るようにした(`Wf1973ContinuousSession.Connect(GeneratorWaveform)` を wrapper に追加。SPEC.md)。直した後の確認が上の表。
