# 雛形の数式整理とExcel事前準備（2026-11-02）

スペックの低いPCで、XDTからExcelへの転送に約2秒かかるとの報告。現場PCは使用中のため、このPCの実Excel（16.0）と同梱の6500点XDT・一時ファイルで確認した。現場PCでの実測は未取得。

## 1. 雛形.xlsxの数式整理

`sheet1` のS・T・W・X列（上昇・下降別の電流・圧力）は21546行目まで数式があり、測定値4〜1303行目に対応する5〜1304行目以外はすべて `#N/A` だった。V・Z列は列全体を対象にAVERAGEIFを2回計算していた。判定（E21・L21）はA・B列だけを参照しており、S〜AA列はヒステリシス表示（AB4→L3）用。

変更はExcelで雛形を開いて行い、保存し直した。

- S・T・W・X列：5〜1304行目だけ残し、1305〜21546行目を削除。
- `ROUND(VLOOKUP(A4,$A:$A,1,0),4)` 等、自分自身の値を完全一致で探すVLOOKUPを `ROUND(A4,4)` 等の直接参照へ置き換え。
- V・Z列：`IF(ISERR(AVERAGEIF(…)),"",AVERAGEIF(…))` を `IFERROR(AVERAGEIF(…),"")` に変更。条件範囲がS・T（W・X）と同じ行のため、AVERAGEIFが `#N/A` を返す組み合わせはない。
- 判定式・グラフ・図形・書式・ほかの列は変更していない。ファイルは812KB→227KB、使用範囲はA1:AC21546→A1:AC1628。

雛形は1300点（圧縮5）用のまま。D6・グラフ・MATCH範囲と同様、S〜X列も1304行目までなので、点数を増やす場合は雛形の範囲を見直す。

## 2. LOGGER前面表示中のExcel事前準備

製品の合格確定時にExcelを終了するため、次の製品の最初の転送は毎回、Excel起動・作業ブック作成・ブック表示を伴っていた。

- 参照波形の読み込み操作後（LOGGER前面表示時）と合格確定後に、Excelを表示せずに作業ブックを開いておく。測定値は0で作成し、転送と同じ雛形・転送先・点数の作業ブックにする。最初の転送はブック再利用として全点を上書きする。
- 準備中は転送や値の書き込みに使う操作も一度呼び、初回のCOM呼び出しの準備時間を先に済ませる。
- 測定・他の操作中は開始しない。測定結果がある間、保存後の工程中、動き検査では行わない。準備中（このPCで約1.2秒）は処理中扱いで、測定開始・転送ボタンは無効。M5Stack・画面には「測定待ち（Excel準備中）」と表示する。
- 失敗した場合はログだけを残し、転送時に従来どおり作業ブックを作る。

## 確認

このPC（実Excel 16.0）・同梱XDT・一時ファイルで実施。元の雛形・測定ファイル・機器には書き込んでいない。

旧雛形と新雛形を同じExcelで開き、5種類の測定値（雛形の値、電流・圧力の拡大縮小・ずらし、乱数ノイズ）を書き込んで計算結果を比べた。A1:AC1628のうち、値が違ったのは削除した1305〜1628行目のS・T・W・X列（旧は `#N/A`、新は空欄）の1296セルだけ。旧雛形の1305〜21546行目も全セル `#N/A` だった。E21・L21はOK/OK、NG/NG、NG/OK等の組み合わせがあり、L3（ヒステリシス）も含めて一致した。

| 転送（既存の `--reuse` 検証） | 旧雛形 | 新雛形 |
| --- | ---: | ---: |
| Excel起動を伴う初回転送 | 2721 / 2371ms | 1924 / 2005 / 1711ms |
| 作業ブックを作り直す転送（中央値） | 1377 / 1351ms | 572 / 515 / 586ms |
| ブック再利用の転送（中央値） | 205 / 201ms | 119 / 98 / 147ms |

事前準備（`--prepare`、新雛形）：準備なしの初回転送1767 / 1818ms、事前準備1197 / 1198ms、準備後の最初の転送292 / 277ms。準備後の転送はブック再利用となり、sheet1のA1:AC1628の全値・E21・L21・ヘッダが準備なしの転送と一致した。準備中はExcelを表示せず、転送時に表示した。

旧雛形でもForceFullCalculationのON/OFFで計算時間はほぼ変わらなかった（測定値は毎回全点が変わるため）。

- Releaseビルド成功（警告・エラー0）。
- ExcelHeader：ヘッダ7件、`--optimization` 54件、`--session` 8件、`--transfer` 6件、`--reuse` 16件、`--prepare` 7件すべて成功（新雛形）。
- Verification 92件、AppShutdown 8件成功。
- SaveAvailability（`--no-dialogs --with-excel`、新雛形）成功。追加した実MainFormの確認：他の操作中は事前準備を始めず、終了後に非表示のExcelで準備して待機状態へ戻ること、測定結果がある間はブックを置き換えないこと。

ExcelHeader・SaveAvailabilityの実Excel検証の後、表示なしのExcel（`/automation`）が残る場合がある。事前準備を使わない既存の検証でも同じように残るため、検証コード側で保持しているCOM参照によるものと推定（アプリの終了処理では参照をすべて解放している）。

dotnet run --project Tests/SaveAvailability/SaveAvailability.csproj -c Release -- --no-dialogs --with-excel "$PWD/雛形/雛形.xlsx" "$PWD/雛形/AS110データ調整・データ取り用.xdt"

## 保留中の案：書き込み中の計算を手動にする

測定値を書き込むと自動計算が走り、その後の判定前に明示的な計算をもう一度行っている。書き込みの間だけ計算方法を手動にして、計算を1回にまとめる案。このPCではExcelの計算全体が約0.1秒で、省けるのは数十ms程度のため実装していない。古いPCでは効果が出る可能性があるため、現場PCでの今回の変更後のログ（「計算・判定」の時間）を見てから採用・棄却を決める。
