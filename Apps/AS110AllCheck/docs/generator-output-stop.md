# 発振器の通信失敗時に出力を止められる状態を保つ（2026-11-02）

コードレビュー（対象 d80bef7、プロジェクト資料 `claude/review-2026-11-02.md`）の優先度「高」1・2への対応。

## 問題

1. 状態監視（5秒ごと）の `*IDN?` が1回失敗すると、発振器の接続を即座に破棄していた。破棄後は出力OFFを送る手段がなく、漏れ試験のDC +5Vが出たまま止められなくなる恐れがあった。各SessionのDisposeも出力OFFを送っていなかった。「確認」での応答確認失敗・波形設定失敗時も同様に破棄していた。
2. `StopLeakOutput` は出力OFFの送信に失敗しても `finally` で `_leakOutputReady=false` とし、画面・M5Stack表示上は出力OFF扱いになっていた。

## 変更

- 状態監視の応答失敗では接続を破棄しない。従来どおり「確認」を求める状態にし、漏れ試験出力中は既存のResetTemplate経由で出力停止を試す。
- 「確認」では応答確認を2回まで行う。破棄する場合は先に出力OFFを試し、続けて再接続する（接続時に出力OFF・オフセット0Vを送信）。応答が回復した場合は出力OFFを再送する。
- WF1973／SDG1032XのDisposeで、解放前に出力OFFを試す（タイムアウト500 ms、失敗しても解放は継続）。
- 出力OFFは送信に成功したときだけ `_leakOutputReady` を解除する。失敗時は新しい「出力状態不明」状態にする。
  - 発振器表示に「出力状態不明」（赤）、工程表示に本体でのOFF確認と「確認」での再接続を案内する。
  - 出力状態不明の間は `ConnectionsReady` をfalseとし、測定開始・+30mA・漏れ試験・合格へ進ませない。
  - 解除は出力OFFの送信成功（「再測定へ戻る」での再試行を含む）か、再接続の成功だけで行う。
  - 状態監視中に停止失敗した場合は警告ポップアップを1回表示する。終了処理中・「確認」中は表示せず、「確認」では結果のエラーにまとめる。
- [終了処理の変更](application-shutdown-errors.md)で行っていた「出力停止が失敗しても漏れ試験開始準備済みのフラグを解除する」動作は、本変更で置き換えた。終了処理は従来どおり失敗しても継続する。

## 確認

- 終了イベントテスト（`Tests/AppShutdown`）に2条件を追加した：漏れ試験出力中の終了で停止成功（フラグ解除）／停止失敗（出力中・出力状態不明のまま、停止の再試行は1回だけ、ダイアログなし）。
- 変更はClaudeがLinuxのクラウド環境で行った。.NET SDK・NuGet・VISA COMを取得できない環境のため、ビルド・テスト実行は未実施。差分の読み直しと括弧の対応のみ確認した。
