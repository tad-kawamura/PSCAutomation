# 電流・圧力のXDT校正（2026-11-02）

## 変更

NR-500で使う作業用XDTに、CH1電流・CH2圧力の2点校正をGUIから反映する。動き検査・データ調整・データ取りに適用する。低点と高点それぞれの入力電圧（V）・対応する実測電流（mA）／圧力（kPa）を編集でき、ゼロ点も固定しない。

**2026-11-06 改訂**: スタンド選択は廃止し、接続確認とモード選択の両方が済んだら校正画面を自動で開く。校正画面は「電流」「圧力」の枠ごとに 1（低点）・2（高点）の計測値（V）と表示値（mA／kPa）を縦に並べる。初期値は雛形の値（スタンド公称値・前回値は使わない）。記録は保存先の `校正記録` フォルダーへ（[校正記録の保存](calibration-history.md)）。横軸拡大は廃止。以下は改訂前の記述で、「スタンド選択」は「モード選択後の校正画面」と読み替える。

校正画面を開き、「適用」で作業用XDTを生成してLOGGERへ読み込む。キャンセル時はLOGGERを閉じず、適用済み設定を保持する。元の雛形は変更しない。校正ごとに別の一時フォルダーへ出力し、LOGGERで開いている作業用ファイルを上書きしない。適用後は参照波形を再選択する。

初回の電流値は従来のスタンド公称値、圧力値は選んだモードの雛形から読む。適用ごとに適用日時と8項目の値を校正記録へ追記する（機器識別名の入力・前回値の再利用は2026-11-02に廃止）。詳細は [校正記録の保存](calibration-history.md) を参照。

「電流・圧力の校正値を変更」は、接続済み・LOGGER停止・未測定のときに使える。測定結果・保存失敗・一時保存失敗・漏れチェック等が残る間は変更できない。未保存の測定結果を変更する場合は既存の「設定変更（測定を破棄）」を先に行う。校正ダイアログ中は既存の操作排他で測定開始を防ぎ、適用直前にも接続とLOGGER停止状態を確認する。LOGGERへの読み込みに失敗した場合は適用済み扱いにしない。

数値には小数点 `.` を使用する。非数値・非有限値、低点以上になっていない高点の電圧／実測値を拒否する。XDT形式のfloat32で保存するため、LOGGER従来設定と同じ精度となる。

## 不具合：スタンド選択後に校正画面が出ずフリーズ（2026-11-02修正）

データ調整ver1（`5f48979` から発行）の実機確認で、データ調整を選択してスタンドを選ぶと、校正画面が表示されないまま操作できなくなった。

修正：校正画面を最前面に表示する。値の確認・エラーのポップアップは従来から最前面。

確認：最前面の所有者に対して校正画面をモーダル表示する検証を追加（`SaveAvailability --calibration-foreground`）。修正前は `TopMost=False`・所有者より背後で失敗し、修正後は3回とも最前面・所有者より前面で成功。Releaseビルド（警告・エラー0）、SaveAvailability（`--no-dialogs`）成功。この開発PCではMainFormを表示する既存の前面表示検証（ダイアログありの実行）が機器の初期化で止まるため、MainForm自体を所有者にした確認はできていない。

### 恒久対策の試行と取り消し：準備画面を最前面に固定しない（2026-11-02、f83a24f→取り消し）

### 準備画面の最前面固定をやめる（2026-11-11、ver2.02 の実機確認から）

経緯：ver2.02 で LOGGER の前面化を Excel と同じ強い方法（`WindowActivation.TryActivate`）にしたが、現場の確認でデータ調整・漏れ試験のときにアプリのメイン画面が LOGGER より前に出てうまくいかなかった（人の報告）。人の指示で、以前から懸念していた準備画面（MainForm）の最前面固定をやめた。1.0.2 で同じ固定解除を試して取り消したときは、LOGGER を前に出す処理が `SetForegroundWindow` 1 回だけで弱かった。

変更：
- 接続確認・雛形の状態変化でアプリを前に出すときは、一度だけ最前面にして重なり順を上げ、すぐ通常表示へ戻す（`KeepPreparationInFront`）。入力先は `WindowActivation.TryActivate` で切り替える。参照波形の選択前なら約0.8秒後に、アプリが前面でなければ1回だけ前へ戻し直す（LOGGER の起動・雛形読み込みで LOGGER が遅れて前に出る分）。
- データ調整開始・漏れ試験実施・参照波形の読み込み後は、LOGGER を前に出した約0.5秒後に LOGGER が前面か確かめ、外れていれば1回だけ出し直す。そのとき前にいた画面（アプリのメイン画面・ほかのプロセス名と窓の題名）をログに残す。アプリのポップアップ（警告など）が前のときは入力先を奪わず、出し直さない。
- ポップアップ・ダイアログ（校正画面・合否・保護解除・転送設定・警告）の最前面指定はそのまま残す。
- 準備中に作業者が LOGGER をクリックした場合は、LOGGER が前面になる。

未確認：実際の LOGGER・M5Stack をつないだデータ調整・漏れ試験での前面切替。この開発 PC では、実 MainForm を表示する前面表示検証（ダイアログありの SaveAvailability）が機器の初期化で止まるため実行できていない。0.5秒後の出し直しで足りない（もっと後にアプリが前に出る）場合は、ログの「LOGGERの前に〜が出たため」の行で原因を切り分ける。

### 合否ポップアップでメイン画面を連れてこない（2026-11-11）

経緯：設定を終えたあとはメイン画面をほぼ見ないので、前に出てきてほしくない（人の要望）。合否ポップアップはメイン画面を持ち主にして出していた。Windows は持ち主つきの窓を前に出すと持ち主も一緒に前へ出すため、Excel 転送のたびにメイン画面が Excel・LOGGER より前に出ていた（持ち主つきの最前面ポップアップを前に出すと持ち主がほかのプロセスの窓より前に来ることを、この PC で PowerShell の実験で確認）。

変更：合否ポップアップを持ち主なしで出す（最前面・約0.4秒で自動で閉じる・Enter で早く閉じる動きは同じ）。持ち主なしでは `OwnedForms` に入らないので、「表示中のポップアップから入力先を奪わない」判定に合否ポップアップを足した（`PopupVisible`）。メイン画面を閉じるときに合否ポップアップも閉じる。「合格しているけど、またやるの？」と警告・エラーのメッセージは、人の判断で持ち主つきのまま（出るとメイン画面も一緒に前に出る）。

確認：SaveAvailability に「合否ポップアップに持ち主がない」検査を足し、修正前のコードで失敗・修正後で成功。実 MainForm を表示する検証だけを飛ばす `--no-mainform-display` を足し、この PC で合否ポップアップの検証（入力先・Enter・自動で閉じる・再実行の確認）と実 Excel を使う検証（`--with-excel`）25 件が成功。Verification・AppShutdown・SaveAvailability（`--no-dialogs`）も成功。

### M5Stack から始めると LOGGER が Excel の後ろに残る（2026-11-11、ver2.04 の実機確認から）

経緯：ver2.04 の実機で、M5Stack の B ボタンで漏れ試験を始めたとき、ログに「漏れチェック：Windowsが切り替えを許可しませんでした（前面=EXCEL「work.xlsx - Excel」）」、約0.5秒後の出し直しも「Windowsに拒否されました」と出て、LOGGER が前に出なかった（人の報告と画面の写真）。データ調整でも同じ状態（人の報告）。M5Stack からの操作ではアプリが人の操作を受けていないので、Windows が入力先の切り替えを断り、入力スレッドをつなぐ回り込みも効かなかった。さらに、`TryActivate` の最初の手順（重なり順を HWND_TOP へ）だけでは、前面の Excel の上に出ないことをこの PC の実験で確認した（PowerShell で 2 つの窓を作り、Excel 役を前面にしたまま LOGGER 役に HWND_TOP → 重なり順は変わらず。最前面にしてすぐ戻す → Excel 役の上に出て、入力先は Excel 役のまま）。

変更：共通部品 `WindowActivation` に `BringToTop`（一度だけ最前面にしてすぐ戻す。入力先は変えない）と `IsAbove`（重なり順の比較）を足した（人の確認済み。既存の関数は変えていない）。LOGGER の前面表示（データ調整開始・漏れ試験実施・参照波形の読み込み後）は、先に `BringToTop` で画面を上に出し、そのうえで `TryActivate` で入力先の切替を試す。入力先を断られても LOGGER が前面の窓より上に見えていれば「LOGGERを前に出しました（…キーボードの入力先は〜のまま）」とログに出す。約0.5秒後の確認も、LOGGER が前面の窓より上に見えていれば出し直さない。

確認：全体 `PSCAutomation.sln` の Release ビルド。`Common.Tests` に `BringToTop`・`IsAbove` の検査（通常の窓の一番上へ出し、最前面に固定しない）を足して成功。そのほかの `Wrappers/Tests`、Verification・AppShutdown・SaveAvailability（`--no-dialogs`、`--no-mainform-display --with-excel` 25 件）が成功。

追加確認（2026-11-12、開発 PC で人の操作あり）：人が Excel 役の窓をクリックした直後（Windows が前面の切り替えを断る状態。現場の M5Stack 操作と同じ）に、人の操作を受けていないプロセスから LOGGER 役を前に出す実験をした。今の方法（`TryActivate` のみ、ver2.04）は戻り値 false で、LOGGER 役は Excel 役の後ろに残った（現場の失敗を再現）。新しい方法（`BringToTop` → `TryActivate`）は戻り値 false（入力先は Excel 役のまま）だが、LOGGER 役は Excel 役の上に出た。前に作業者が触らない間は Windows の制限が時間切れ（既定 200 秒）で外れるため、以前の実験では「断られる」状況を再現できていなかった。

未確認：実機（実際の LOGGER・Excel・M5Stack）で LOGGER が Excel の上に出ること。キーボードの入力先は Excel のままになる（LOGGER はキーボードで操作しないので支障ない、人の確認）。
