# YDT一時保存とExcelヘッダ表示（2026-10-28）

ユーザー報告：データ調整で「LOGGERの一時保存に失敗（戻り値1）」となる。YDTでマニュアルトリガを使用し、収集後に停止していないためではないか、との推定。長期的にマニュアルトリガ運用をどうするかはユーザーが検討中であり、今回の対処で最終方針を確定したわけではない。

調査：旧処理ではLOGGER Xを全モードでStart→Trigger（次回からTriggerのみ）とし、GetState=3（トリガ待ち）も測定完了としていた。共用YDTにはリピート・マニュアルトリガが設定されていた。インストール済みメーカー資料 `WLXAuto_M_E.pdf` の7.3.2.1は収集中のSaveFileを不可とする。原因の説明とは整合するが、報告時の機器状態・COM状態ログを採取しておらず、実機で原因を確定・再現したものではない。

当面の対処：データ調整・データ取りでは毎回Startだけを発行し、Triggerを送らない。共用YDTはメーカーUIでリピートOFF・マニュアルトリガOFFに変更し、2ms・6500点の1回収集で停止させる。設定をYCF保存した後、メーカーCOMのOpenFile / SaveFileでYDTを出力した。新YDTのSHA-256は `D88FFFFC39EA03511D6BA145E7DEE1BCA44468F8B0ECD63D5F7FA350BB4B520C`。再読込して周期・点数と両設定OFFを確認済み。元のDドライブのファイルは変更していない。

GetState=3・10・12を完了とせず、1（完全停止）まで待つ。保存直前にも1を確認する。動き検査は従来のマニュアルトリガ処理を維持する。

Excel：ヘッダのTextRange全体へのText代入が、雛形の文字別のフォント・サイズ・太字・下線を崩す処理だった。型式・S/N・供給圧力・測定日の値だけをCharactersで後ろから置換し、ラベル・空白・改行・書式を維持する。元のExcel雛形は変更しない。

確認：Releaseビルド、既存Verification、LOGGERの模擬APIによる回帰検証に成功。単発収集は2回のStartでTriggerが0回、状態3→10→12→1のうち1だけで完了することを検証。実Excelの読み取り専用雛形で、型式・S/Nの桁数増減と供給圧力・日付変更後に、対象文字のフォント・サイズ・太字・下線が一致することを確認。

実Excel確認の再実行（Excelが必要）：

```powershell
dotnet run --project Tests/ExcelHeader/ExcelHeaderTests.csproj -c Release -- "検査アプリDLLの絶対パス" "Excel雛形の絶対パス"
```
