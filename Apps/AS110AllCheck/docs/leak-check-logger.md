# 漏れチェックのLOGGER連動（2026-10-28）

2026-11-12 追記：試験秒数を画面で変えられるようにし（基本10秒）、NR-500では試験中に圧力を読み出して合否を自動判定するようにした。不合格・判定できないときは「合格」を押せず、結果は保存先の「漏れ試験記録.txt」に残す。以下の「合否は人」「10秒」「結果を保存しない」は2026-10-28時点の記録。現在の動きは [operation.md](operation.md)「漏れ試験の自動判定」、決めたことは specs/AS110AllCheck/SPEC.md。

保存処理はユーザーから良好との確認を受領し、変更しない。漏れチェックで発振器に加えてLOGGERの収集を連動させる。

正式保存後、LOGGERの完全停止を確認してから前面表示を要求する。現在開いている共用のデータ調整・データ取り雛形をそのまま使い、毎回Startを実行する（Triggerは送らない）。開始成功後にDC +5Vを出力し、LOGGER開始から10秒を基準に出力OFFとLOGGER Stopを実行する。Stop後は状態1（完全停止）を最大5秒待つ。Windowsのスケジューリング・COM処理・機器応答に伴う遅延はあり、厳密なハードウェア同期ではない。

通常測定のrevision・一時保存・Excel・正式保存済みファイルは変更しない。漏れチェックの収集結果を自動保存しない。正常終了・完全停止・通信確認後だけ漏れチェック回数を加算する。次の漏れチェックでも同じ雛形でStartから実行する。

LOGGER開始失敗・発振器出力失敗・終了要求・停止失敗でも、出力OFFとLOGGER停止を個別に試みる。一方の停止失敗で他方の停止を省略しない。処理失敗と停止失敗が重なった場合は両方の例外を保持する。停止未確認では漏れチェック成功としない。前面表示の失敗はログへ記録し、収集・出力は実行する（既存の参照波形読込後の表示方針と同様）。

検証：Release/DebugビルドとVerification。新しい機器なし検証では実時間の10秒待機、LOGGER開始→出力→両停止の順序、開始失敗時の出力抑止、出力失敗・終了キャンセル・片側停止失敗での両停止試行を確認する。DebugのVISA参照MSIL/AMD64警告、VerificationのNU1900通信警告は別途記録する。
