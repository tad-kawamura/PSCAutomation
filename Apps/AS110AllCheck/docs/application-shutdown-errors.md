# 通信エラー時もアプリの終了処理を継続（2026-11-02）

実機準備を中断した後、LOGGERは終了済みだったが、検査アプリの終了操作は発振器のVISAエラー `0x80040000` で繰り返し失敗した。実測・Excel転送は未実施（revision=0）。その場では起動パスとPIDを照合した検査アプリだけを終了して復旧した。

## 原因と変更

従来のOnFormClosingは、StopLeakOutput・LOGGERのShutdownAsyncを同じRunOperationAsync内で行い、どちらかが例外を返すと終了完了フラグが立たずフォームが残っていた。OnFormClosedの接続解放も、途中で例外が出ると後続を飛ばす構造だった。

- 終了処理を `UI/MainForm.Shutdown.cs` へ分離。出力停止、LOGGERの停止・終了、Wi-Fi復帰、Excel・M5Stack・発振器・LOGGERの解放、一時ファイル削除を個別に実行し、途中の例外では後続を止めない。
- 終了時に機器エラーのモーダルダイアログを表示しない。エラーとHRESULTを `SHUTDOWN_ERROR` として診断ファイルへ保存し、最後にログをフラッシュする。機器の停止未確認とアプリの終了手順完了を区別する。
- 処理中の終了要求を保持し、処理が戻ったfinallyからCloseを再要求する。終了処理と進行中のCOM操作を重ねず、終了ボタンの連打でも停止・解放を重複実行しない。
- 漏れ試験中は既存のキャンセル・両機器停止の処理を待って終了する。終了開始後は状態監視と操作受付を止める。通信切断・処理失敗の追加ポップアップやExcel前面表示も抑止する。
- 測定準備から処理中フラグを立て、終了要求後はLOGGER開始待ちから戻っても追加トリガーを送らない。漏れ試験の出力開始直前にも終了要求を確認する。出力停止が失敗しても「漏れ試験開始準備済み」のフラグを解除する。
- LOGGER共通wrapperの通常の再接続・停止確認仕様は変更しない。終了に失敗したLOGGERを名前で強制終了したり、別のExcel・LOGGERを終了したりしない。

## 検証

機器へ接続せず、実際のMainFormを生成し、発振器・LOGGERのAPIだけを模擬した終了イベントテストを追加した。フォームのShowは呼ばないため、起動時の実機接続は実行されない。

次の9条件で、フォームの終了が一度だけ完了すること、後続の接続解放が行われること、終了を阻むモーダルダイアログが出ないこと、失敗が診断ファイルへ残ることを確認した。

1. 正常終了
2. 発振器のStopOutputでVISAエラー
3. 発振器のDisposeで接続解放エラー
4. LOGGERのStopでCOMエラー
5. 発振器停止・解放とLOGGER停止がすべて失敗
6. 非同期処理の途中で終了要求を受け、処理がCOMエラーで戻る
7. 非同期処理の途中で終了要求を受け、処理が正常に戻る
8. 同期処理中の終了要求とCOMエラー
9. 漏れ試験中の終了要求・キャンセル完了後の終了

各条件でCloseを重ねて呼び出し、停止・解放が一度だけ行われることも確認した。異常系を正常終了と記録せず、失敗・未確認件数を残すことを確認した。

```powershell
dotnet run --project Tests/AppShutdown/AppShutdownTests.csproj -c Release
```

既存Verification全件とSaveAvailabilityの機器なしチェックも成功。Debug/Releaseビルド成功。最終Releaseビルドは警告・エラー0、Debugは既存のVISA参照MSIL/AMD64不一致警告1件。初回ビルド時のNU1900は依存パッケージの脆弱性情報取得の通信警告であり、機器通信の検証結果ではない。

未確認：実機のUSB切断・電源断を伴う終了、NR-X/Wi-Fi復帰、漏れ試験中・測定準備中の実機終了操作。機器のAPI呼び出し自体が戻らない場合の強制解除は今回追加していない。機器の停止が確認できない場合もアプリは終了するため、診断ログの停止未確認を実機停止済みとは扱わない。M5Stackのスケッチ変更・書き込み、発行物の更新は不要／未実施。
