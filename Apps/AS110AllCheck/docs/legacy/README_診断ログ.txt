Arduino通信の診断ログ追加版

適用元：前回のスタンド別スケーリング修正版 AS110BoltCheck_StandScaling_v3。
1. Visual Studioを閉じ、現在のコードをバックアップしてください。
2. ZIP内の5つの.csをプロジェクトフォルダへコピーしてください。
   ArduinoDiagnosticLog.csは新規ファイル。他4つは置換します。
3. リビルドして、通常どおり発行してください。
4. Arduino IDEでAS110_NfInterlock.inoを開き、UNO R4 Minimaへ書き込んでください。
   D7=NF入力、D12=ボタン、D0/D10=LED電源。元ファイルの配線・離しトリガを維持。
   現地でこの配線を変更している場合は、現行inoにも同じ診断送信を反映してください。
   C#だけでも受信停止・COM消失・例外を記録できます。再起動確認にはinoも必要です。

ログ：exeと同じ場所のLogs/Arduino_起動日時_プロセスID.log。
書込不可なら %LOCALAPPDATA%/AS110BoltCheck/Logs へ保存します。
起動時の画面ログに保存先を表示します。アプリを閉じても残ります。
約5MBで.previousに退避（前の1世代のみ）。通常は5秒ごとの状態要約を記録。
異常・復旧・接続確認の直前200受信行（NF定期送信なら約50秒）も記録します。
古い起動セッションのログは自動削除しません。

突然の異常が出たら：画面内容や発生時刻をメモし、復旧後でよいので当該.logと
存在すれば同名.log.previousを渡してください。先にUSBを抜き差しする必要はありません。
USB抜き差しや「確認」の操作をした時刻も分かると、原因と復旧操作を区別できます。

記録の意味：
COM_DISAPPEARED：監視対象のCOMがWindowsの一覧から消えた。
PORT_CLOSED：COMはあるがアプリのシリアルポートが閉じている。
RX_STALE：COMはあるが受信行が1秒以上来ていない。
NF_STALE：他の受信はあるがNF状態が1秒以上来ていない。
RECEIVING：受信が正常な状態へ復旧。
SERIAL_ERROR：ErrorReceivedの種類を記録。従来どおり切断通知を出す。
READ_ERROR/WRITE_ERROR/VERIFY_ERROR：例外型・スタック・COM一覧・最終受信経過時間。
APP_RECEIVE_HANDLER_ERROR：C#側の受信処理で例外が発生。
ARDUINO_BOOT：Arduinoの起動通知（接続時の起動・リセットも含む）。
ARDUINO_RESTART：同一の接続中にArduino稼働時間が戻った。
APP：画面へ出したログ。受信継続と画面の通信エラーを時刻で比較できる。

診断監視はUIとは別に0.5秒間隔で動きます。監視による追加の切断や自動再接続は行いません。
0.5秒より短いCOM消失を必ず検出できるわけではありません。
再起動が分かっても、接触不良・電源・外部リセットのどれかは断定できません。
Arduinoの稼働時間は約49.7日で折り返すため、境界付近はUPTIME_WRAPとして記録します。
両方の保存先に書込できない場合、ファイルログは保存できません。

検証：この環境には.NET SDK/Arduinoコンパイラと実機がないため、ビルド・実機動作は未確認。
