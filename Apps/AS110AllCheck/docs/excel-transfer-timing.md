# Excel転送の計算状態と待ち時間（2026-10-28）

ユーザー報告：データ調整は良さそうだが、Excel転送時に「Excelが計算中です。しばらく待って再操作してください。」というポップアップが邪魔。Excel画面への切替に約3秒かかる。

旧処理は転送時にExcelを終了・再起動し、CalculateFull後のApplication.CalculationStateが0以外なら即エラーにしていた。実Excelで、CalculateFullRebuildや各シートのCalculate後も2（再計算待ち）が残る状態を再現。これは1（計算実行中）と異なり、全体状態が0になるのを待つだけでは解消しなかった。

変更：入力シートを先に、その後各シートを明示的にCalculateしてからE21・L21を読む。転送時は計算実行中（1）の間だけ非同期で待ち、30秒でタイムアウトする。2を理由とする計算中ポップアップは出さない。判定完了後だけ転送済みにする。実際の読込・COM・タイムアウト等のエラー通知は維持する。

速度：自分で起動したExcelは再測定時に終了せず、前の作業ブックだけを閉じて再利用する。既存の他のExcelへは接続しない。変更のないヘッダ文字は置換しない。測定データ読込、作業ブック作成、Excel起動／再利用、ブック表示、ヘッダ更新、計算・判定、全体の所要時間をアプリログへ記録する。

確認：Releaseビルド成功（警告・エラー0）、既存Verification成功（NU1900は脆弱性情報の通信警告）。実Excel・同梱XDT/Excelで2回連続転送し、同じExcelインスタンスを再利用すること、計算状態2でも判定まで進むことを確認。作業ブックの判定セルを式でOK/OK→OK/NGに変更して、再計算後の判定が真→偽となり古いOKを使わないことも検証。

最終検証の計測例：初回転送全体3953ms（Excel起動1400ms、ブック表示642ms）、再利用時1449ms（Excel再利用2ms、ブック表示373ms）。画面切替までの時間とは区別する。PC・Excelの状態で変動し、初回起動を含む待ち時間がなくなることを保証するものではない。

再実行：

```powershell
dotnet run --project Tests/ExcelHeader/ExcelHeaderTests.csproj -c Release -- "検査アプリDLLの絶対パス" "Excel雛形の絶対パス" --transfer "6500点の検証用XDTの絶対パス"
```

検証で変更するのは一時作業ブックのみ。元の雛形・測定ファイルは変更しない。NR-X本体からの一時YDT/CSV保存を含む一連操作、ユーザーのPCでの所要時間と実機動作は未確認。
