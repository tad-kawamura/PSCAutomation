# Excel判定とC保存の追従（2026-10-28）

## 再調査による訂正

前回修正後もExcelの両判定が合格なのにPC・M5Stackの保存が無効だった。実データで再調査し、根本原因は判定シートの取り違えと確認した。同梱雛形のworkbook.xmlとrelationshipsを照合すると、判定式があるsheet2.xmlはシート名「sheet1」であり、表示用の「圧縮5」はsheet1.xmlである。従来コードは圧縮5!E21・L21を読み、空欄2つを不合格としていた。前回の下記説明の「圧縮5!E21・L21」は誤り。前回テストも圧縮5にOK式を新設していたため、雛形の本来の判定を検証できていなかった。

修正：判定元を既定sheet1!E21・L21へ変更。転送設定に判定シート名を追加し、既存JSONでは既定sheet1を使う。ヘッダ編集・PDF出力は圧縮5を維持する。保存許可の条件・理由を画面とログへ追加し、通信前の表示内容を機器なしで検証できるように分離した。

実測照合：PCに残っていた15:53のNR-X一時測定データを一時検証ブックへ転送。修正前は圧縮5から空欄/空欄、修正後はsheet1からOK/OKを取得した。元の測定データ・雛形は変更していない。

検証：実Excelで元の判定式を残し、その入力だけを一時ブック内で合格範囲／範囲外へ変えて合否を確認。実際のMainFormを使い、元の判定式→保存ボタン有効→M5Stack C許可ビット1を確認した。NG・空欄・処理中・転送無効化では保存ボタンとC許可ビットが0になる。実機は接続していない。Debug/Releaseビルド成功。DebugではVISA参照のMSIL/AMD64不一致警告、VerificationではNU1900通信警告が出た。M5Stack本体の表示・C操作と正式保存一式は未確認。ファームウェア変更・再書き込みは不要。

再実行：`dotnet run --project Tests/SaveAvailability/SaveAvailability.csproj -c Release -- "Excel雛形" "6500点の検証用XDTまたはCSVを伴うYDT"`。機器へ接続せず、実ExcelとMainFormで一時ブックを検証する。

## 前回の調査記録（上記訂正を参照）

報告：データ取りで転送後のExcelは合格だったが、M5StackのC「保存」が緑にならなかった。

確認した条件：処理中・測定中・漏れチェック中でなく、データ取りモードで、最新測定をExcel転送済み、E21・L21が両方OK、正式保存後の工程に入っていないこと。M5StackはPCの保存ボタンの許可ビットで緑表示し、PC表示の受信が2.5秒途絶えると無効になる。保存先・機器の接続状態はPCの保存ボタン自体の有効条件ではないが、M5Stackの操作受付には通信確認が必要。データ調整では正式保存を行わない。

不整合になり得る経路：旧コードは転送直後に一度だけ判定して値を保持していた。後からExcelの判定が変わっても更新されない。今回の現場のセル値・ログは未取得であり、原因をこの経路に断定はしていない。同梱雛形の圧縮5!E21・L21の式がOK/NGを返すことは確認した。

修正：転送済み・正式保存前の作業ブックを約1秒ごとに監視する。両方OKで保存を有効化し、NG・空欄・計算中・取得失敗で無効化する。計算中を除いて判定値を読み、監視では再計算を強制しない。転送時と保存時の再計算・判定確認は維持する。状態欄に理由を表示し、転送時と監視状態変化時にセル値をログへ出力する。取得失敗は同じエラーを毎秒記録しない。M5Stackファームウェアの変更は不要。

確認：アプリReleaseビルド成功（警告・エラー0、単一ノードで実行）。既存Verification全件成功（NU1900はNuGet脆弱性情報取得の通信警告）。実Excelで同梱XDTを2回転送し、各回の一時作業ブックでOK→NG→空欄→OKの変化を再転送なしで検出できること、従来の明示再計算の判定、Excelインスタンス再利用を確認。元の雛形・測定ファイルは変更していない。

未確認：報告時の測定結果・Excelとログの照合、M5Stack実機の緑表示とC操作、NR-X実測から正式保存までの一連動作。GitHubへのpushは運用PCへの配布ではなく、使用PCでは修正版アプリへの更新が必要。
